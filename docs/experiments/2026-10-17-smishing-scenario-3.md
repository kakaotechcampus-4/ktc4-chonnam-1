# 스미싱 한 사례의 연결 검증

목표는 기존 경로로 `문자 입력 → 분석 중 → 결과 → 자세히 보기 → 결과 확인`을
끝까지 실행하는 것이다. 새 에이전트 루프·질문 카드·상세 웹·격리 페이지 분석은 도입하지 않는다.

## 대표 사례

```text
[CJ대한통운] 주소 불일치로 배송이 보류되었습니다. 배송 확인 앱을 설치해 주세요. <테스트 URL>
```

- 자동 테스트 URL: `https://parcel-test.example.com/`. 예약 도메인 아래의 가짜 주소다.
  MockTransport 안에서만 쓰고 실제 urlscan이나 휴대폰 테스트에 제출하지 않는다.
- 실서비스 검증에는 팀이 관리하는 무해한 공인 HTTPS 페이지 주소 하나를 사용한다.
  단축 주소·리다이렉트·개인정보·실제 APK는 넣지 않는다. 테스트 URL은 배포 설정 작업 전에 정한다.
- 현재 urlscan 제출은 `public`이다. 외부 전송 안내를 확인한 뒤 합성 문자만 보낸다.
- 기대 결과: 문자가 내세운 기관과 앱 설치 요구를 확인한다. 검증된 설치 요구 신호가 있으면
  R1, 없으면 주소 대조 결과에 따라 R8 또는 R9가 나올 수 있다. 원하는 결과를 하드코딩하지 않는다.
- 격리 페이지는 실행하지 않으므로 상세에서 `페이지 내용은 확인하지 않았어요`가 나오는 것이 정상이다.

## 자동 검증

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest tests/test_smishing_service_flow.py tests/test_result_card_renderer.py tests/test_url_utils.py -q
.\.venv\Scripts\python.exe -X utf8 -m pytest -q
```

`tests/test_smishing_service_flow.py`는 FastAPI 스킬 인증, 실제 OpenAI SDK의 구조화 응답 파싱,
AI 분석·사례 검색·공식 주소 대조·카드 조립·작업 저장·자세히 보기·재조회를 실행한다.
LLM·urlscan·카카오 콜백 HTTP만 대체한다. 콜백 성공과 연결 실패를 각각 검증하고,
상세·재조회에서 LLM과 URL 검사를 다시 부르지 않는지 확인한다.
ASGI 테스트는 백그라운드 완료까지 기다리므로 첫 응답의 실제 5초 제한을 입증하지 않는다.

FE PR #97은 기존 R1·R9 버튼의 연결 검증과 관리자센터 안내만 추가한다.
카드 JSON·문구·이미지·버튼은 유지한다. R8에는 자세히 보기 버튼을 추가하지 않는다.
실제 모델이 R8을 반환하면 그 결과를 기록하고, 버튼 확장은 별도 검토한다.
실제 화면 검증은 관련 PR이 승인·통합된 뒤 수행한다.

## Chrome 변경 제안 — 승인 전 미실행

현재 Render·카카오 설정은 아직 열어 보지 않았다. 아래는 충족해야 할 조건이며,
기존 설정이 일치하면 변경하지 않는다. 저장·배포 전에 대상과 차이를 사용자에게 보고한다.

| 대상 | 확인·변경안 |
| --- | --- |
| Render 서비스 | 저장소와 배포 브랜치가 승인된 `test/render`인지 확인 |
| Render 빌드 | 저장소 루트에서 `pip install -r requirements.txt` |
| Render 실행 | `uvicorn main:app --host 0.0.0.0 --port $PORT --workers 1` |
| Render 환경 | `APP_ENV=staging` 또는 `production`, LLM 세 키, `URLSCAN_API_KEY`, `KAKAO_SKILL_SECRET`, 실제 관측한 `KAKAO_CALLBACK_HOSTS` 설정 확인 |
| 격리 기능 | `ENABLE_URL_COLLECTOR_SHADOW=false`. 이번 링크는 단축 주소가 아니므로 격리 서버 설정 불필요 |
| 카카오 스킬 | HTTPS `<Render 서비스 URL>/kakao/skill`, `X-Skill-Secret` 헤더가 서버와 일치, 문자 분석 콜백 사용 |
| 문자 입력 | 사용자가 붙여넣은 문자가 스킬로 들어오고 고정 응답이 스킬 결과를 가리지 않도록 연결 |
| 자세히 보기 | 기존 블록 `6aad3abfe745d3358bd90c8d`에 같은 스킬 연결, `action.clientExtra.job_id` 전달 확인 |
| 결과 확인 | 블록 이름/실제 요청의 `intent.name`이 `결과 확인`, `결과 확인`·`결과 확인하기` 발화 등록 |

- 메모리 작업 저장소를 유지한다. 한 인스턴스·한 worker에서 시험하고, 진행 중에는 재배포하지 않는다.
- 무료 서비스의 휴면 복귀 시간이 첫 응답에 영향을 주는지도 측정한다. 요금제 변경은 별도 승인 대상이다.
- 공유값은 기존 설정을 재사용하고 로그·문서·PR에 노출하지 않는다. 비밀값 회전은 이번 작업에 포함하지 않는다.
- 두 대시보드의 기존 설정을 보존한다. 새 블록 생성·기존 블록 삭제·운영 채널 배포는 별도 보고한다.

## 휴대폰 검증 기록 — 미실행

| 단계 | 합격 기준 | 실제 결과 |
| --- | --- | --- |
| 첫 이용 | 외부 전송 안내에서 문자 입력으로 이동 | 대기 |
| 문자 입력 | 분석 중 응답이 5초 안에 도착 | 대기 |
| 최종 결과 | 설치 중단·공식 경로 확인 안내, 전체 분석 45초 제한 안 완료 | 대기 |
| 자세히 보기 | 해당 문자의 근거·미분석 범위 표시, 전화번호가 끊기지 않음 | 대기 |
| 결과 확인 | 같은 결과와 확인 시각, 재분석 없음 | 대기 |
| 콜백 실패 | 분석이 저장된 경우 결과 확인으로 조회 | 자동 테스트만 수행 |

실행 시 배포 커밋, 단말/OS, 첫 응답·최종 결과 소요 시간, 익명화한 화면과
콜백 상태를 기록한다. 실패하면 LLM·urlscan·콜백·블록 연결 중 어느 단계인지 구분한다.

## #93 설계와의 관계

새 `start_case`·`resume_case`·`expire_case`와 `AGENT_MODE`는 아직 코드에 없다.
환경변수만 켜서 전환할 수 있는 기능이 아니다. 기존 API와 판정 경로를 유지하고,
질문·답변과 새 `evidence` 계약으로의 전환은 별도 승인·구현한다.
