# 지연 예산

카카오 스킬의 첫 응답은 5초 안에 나가야 한다. 콜백이 있는 요청은 분석 작업을
백그라운드로 넘기고 대기 카드를 반환한다. 최종 결과는 저장한 뒤 콜백으로 전달하며,
전송 실패 시 같은 결과를 "결과 확인"으로 조회한다.

## 현재 구현의 상한

| 단계 | 상한 | 초과 시 |
| --- | --- | --- |
| 첫 응답 | 카카오 제한 5초 | 분석을 기다리지 않고 대기 카드 반환 |
| 전체 분석 | 45초 | 작업을 취소하고 시간 초과 결과 저장 |
| 자체 격리 API | 15초 | 확보한 문자 근거를 유지하고 페이지 수집 실패 표시 |
| 격리 HTTP 수집 | 기본 3.5초 | 수집 실패 또는 부분 수집 결과 |
| 선택적 브라우저 수집 | 기본 6초 | HTTP에서 확보한 자료와 실패 사유 유지 |
| 격리 API 내부 정리 여유 | 3초 | 단계 상한의 합을 넘으면 취소 |
| 문자 정보 추출 | 30초 | 폴백 |
| 사례 검색 | 1초 | 미확인, 추출과 병렬 실행 |
| 문자 위험 신호 제안 | 30초 | 확보한 문자 자료와 실패 사유 유지 |
| 페이지 의미 분석 | 2초 | 확보한 HTML 관측과 실패 사유 유지 |
| 콜백 HTTP 전송 | 10초 | 저장 결과의 조회 폴백 유지 |
| 통화 STT | 30초(실측 2~11초) | STT 실패는 대본 없음 결과(`not_analyzable`). 화자는 나누지 않는다([ADR 0007](adr/0007-no-speaker-diarization.md)) |
| 통화 주장 읽기 | 12초 | 어휘표 폴백, `failures`에 `timeout` |
| 통화 사례 검색 | 1초 | 미확인(`similar_cases:timeout`), 읽기와 병렬 실행 |
| 통화 분석 전체(`analyze_call`) | 40초 | 남은 단계를 건너뛰고 `unchecked`에 `timeout` |

문자 추출·신호 제안의 30초는 시나리오 테스트 설정이다. 두 순차 단계가 각 상한을
모두 사용하면 45초의 BE 전체 분석 제한에 먼저 걸린다. 전체 분석 45초와 콜백 HTTP
전송 10초는 별도 상한이며, 카카오의 실제 콜백 수락 시간을 보장하는 값은 아니다.
여러 URL은 순서대로 수집·분석하므로 같은 45초 예산을 공유한다.

통화 STT는 whisper-large-v3로 확정했다(`ai.case.transcript.transcribe_call`, `asyncio.wait_for`로 30초).
2026-10-28 FSS 녹음 10건 실측에서 STT는 2~11초였다. 같은 실측에서 화자 분리(Claude Sonnet 5.5)는 평균 4.9초
(환각으로 벗어난 1건 제외, 한도 20초)였고 STT와 합쳐 약 12~16초였는데, ADR 0007로 화자 분리를 없애 그만큼 줄었다. 통화 사례 검색은
색인 콜드 적재가 약 1.4초라 기동 시 `warm_up_voice_case_search()`로 미리 채운다.
붙일 사례가 있으면 사례 첨부 관문(`ai.case.attach_gate`, 순수 Python 선형 모델)이 추가로 돈다: 추론 p50 1.6ms · p95 약 5.6ms · 최대 약 16ms(대본 최대 약 1.5만 자), 모델 적재 약 30ms. 적재는 `warm_up_voice_case_search()`가 색인과 함께 미리 하므로 1초 검색 예산에 거의 영향이 없다.
통화 분석은 카카오 첫 응답 뒤 콜백 경로로 수행하며, STT는 `analyze_call` 호출 전에 끝나므로 `analyze_call`의 40초 예산에 들지 않는다. 주장 읽기의 바깥 한도는 12.5초(12초 + 폴백이 먼저 나오도록 둔 0.5초 여유)다.

BE는 `analyze_call`에 `time_budget_s`를 넘길 때 기본값 40초를 그대로 쓰지 않고, 40초(전체 분석 45초에서
카드 렌더링·저장 여유 5초를 뺀 값, v3 B3)에서 이미 쓴 다운로드·STT 시간을 뺀 값(`40 - 경과 초`)을 준다.
기본값을 그대로 쓰면 STT에 쓴 시간(최대 30초)만큼 45초 제한을 넘을 수 있다.
`45 - 경과 초`도 안 된다. 분석이 45초를 다 쓰면 카드를 만들기 전에 전체 분석 상한이 작업을 취소한다. 또 BE는 기동 때 반드시
`warm_up_voice_case_search()`를 호출하고 끝난 뒤에 요청을 받는다. 호출하지 않으면 첫 통화 요청이
색인 콜드 적재(약 1.4초)와 관문 모델 적재(약 30ms)를 떠안아 사례 검색 1초 예산을 넘긴다.

## 실행 순서

문자 분석과 첫 URL의 격리 수집은 병렬로 시작한다. 수집은 URL마다 한 번 수행하고
그 결과를 단축 주소 해석·공식 도메인 대조·페이지 분석에 공유한다. urlscan 제출이나
결과 폴링은 수행하지 않는다. 메인 서버는 입력 링크에 직접 접속하지 않는다.

HTTP 수집은 리다이렉트 최대 5홉을 따른다. 브라우저는 설정된 모드와 트리거에 따라
추가로 실행한다. 공개 모드는 HTTPS/443만 지원하며, 내부 주소나 보호 호스트로의
이동은 차단한다. 부분 수집 사유는 HTML을 분석한 뒤에도 유지한다.

사례 검색은 추출과 병렬로 수행하며 기동 시 `warm_up_case_search()`로 KB와 색인을
미리 채운다. 기동 준비가 끝난 뒤 요청을 받는다. URL 결과 캐시는 구현하지 않았고,
카카오 작업별 결과 저장·조회만 제공한다.
