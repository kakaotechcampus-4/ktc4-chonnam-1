# ADR 0009 — 브라우저 수집을 거쳐도 기록이 모두 공식이면 공식 판정을 유지한다

상태: 채택 (2026-11-06 적용). 제안 2026-11-03

## 맥락

`build_ai_url_analysis` 는 브라우저 수집이 돌면 결과와 상관없이 공식 판정을 `unresolved` 로 내렸다(`2e1c363`).
브라우저 이동 기록은 메인 프레임에 확정된 문서만 담아, 스크립트가 공격자 주소로 보낸 뒤 그 주소가 HTTP 302 로 공식 주소에
돌려보내는 경유가 보이지 않기 때문이다.

그런데 스크립트로 이동하는 공식 사이트가 많다. 2026-11-03 첫 페이지 확인에서 응답한 9곳 중 5곳(CJ대한통운, 로젠,
우체국, 롯데, 경동)이 스크립트로 이동했다. 이런 사이트는 늘 `판단하기 어려워요` 로 끝나, 정상 링크를 확인하려는 사용자에게
결론을 주지 못했다.

## 결정

브라우저가 돌았다는 사실만으로 내리지 않는다. 다음 중 하나면 `unresolved` 로 내린다.

- 브라우저 수집에 실패가 있다(`BROWSER_FAILURE`).
- 내려받기가 일어났다(`BROWSER_DOWNLOAD`).
- 이동 기록이 비어 있다(`BROWSER_CHAIN_EMPTY`).
- 이동 기록, 이동 요청 기록, 최종 주소에 그 브랜드의 공식 도메인이 아닌 호스트가 있다(`BROWSER_NON_OFFICIAL_HOP`).

이동 요청 기록(`navigation_requests`)은 메인 프레임의 모든 이동 요청이라 HTTP 302 로 지나간 경유까지 담는다. 비어 있으면
`BROWSER_CHAIN_EMPTY`, 20개를 넘으면 수집기가 `browser_navigation_limit` 실패를 남겨 `BROWSER_FAILURE` 로 내린다. 맨 앞의
단축 주소는 입력 링크이므로 건너뛴다.

마지막 경우 걸린 호스트만 `[OFFICIAL_HOP] demotion_host=` 줄로 남긴다. 경로·쿼리는 남기지 않는다. `[OFFICIAL_CHECK]` 줄에는
지금처럼 호스트를 넣지 않는다.

## 결과

- **수집기 재배포 전의 위험.** 구버전 수집기는 이동 요청 기록을 보내지 않아(`None`) 이동 기록만 대조한다. 공식 주소 → 스크립트 →
  공격자 주소 → HTTP 302 → 공식 주소 경로가 공식으로 안내될 수 있다. EC2 를 재배포하면 이 경로는 판단 보류로 내려간다.
- **남는 위험.** 브라우저가 페이지를 스냅샷한 뒤에 일어나는 이동과, 브라우저 실행 조건에 걸리지 않아 2단계에서 끝난 페이지의 스크립트는
  보지 못한다.
- 정상 카드는 여전히 문자·페이지 분석이 모두 `no_risk_found` 일 때만 나온다. 브라우저가 본 페이지의 위험 근거는 그대로 쓴다.
- 등록 도메인 밖을 거치는 공식 사이트는 계속 판단 보류가 된다. 잘못된 경고는 아니다. 호스트 로그로 실제 사례를 모아 검토한다.
- 공식 도메인 목록(`services/official_domains.py`)에 경유 호스트를 넣지 않는다. 서브도메인까지 공식이 되어, 공격자가 그 서비스에
  만든 페이지가 공식으로 안내될 수 있다.

## 다시 볼 때

모든 수집기가 이동 요청 기록을 보내게 되면, 기록이 없는 응답(`None`)도 판단 보류로 내리고 구버전 분기를 지운다.

2026-11-06에 적용했다. EC2 수집기 컨테이너가 이동 요청 기록을 보내는 코드임을 파일 해시로 확인했다. 이제 기록이 없는 응답은 `invalid_response`로 판단 보류가 된다.
