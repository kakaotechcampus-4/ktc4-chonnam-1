# ADR 0008 — 통화 녹음은 화자를 나누지 않고, 문장 꼴로 받는 사람 쪽 말을 거른다

상태: 제안 (2026-10-31)

## 맥락

통화 분석(`transcribe_call`)은 whisper 로 받아쓴 뒤 LLM(Claude Sonnet 5.5, `ai/src/ai/llm/diarize.py`)에게
문장마다 `화자1`·`화자2`·`기타` 를 고르게 했다(스펙 D1). 판정(`gate.py` L-3)은 "상대 화자의 기관·지인 주장 +
요구"일 때만 `suspected` 를 냈고, 화자 분리가 실패하면(U-4) L-3 을 쓰지 않았다.

- **느리다.** 2026-10-28 FSS 녹음 10건 실측에서 화자 분리는 평균 4.9초, 한도는 20초다(`docs/latency-budget.md`).
  STT 뒤에 순서대로 돌아 콜백 45초 예산을 그만큼 먹는다.
- **사례 데이터에 화자 표기가 없다.** 통화 KB 와 실제 평가 대본(FSS·KorCCVi)은 화자 구분 없는 한 덩어리 글이다.
  사례 검색 질의도 이미 대본 전체를 쓴다(`voice.py`).
- 화자 분리를 그냥 빼면 L-3 이 영영 서지 않는다(U-4). 반대로 U-4 를 풀고 대본 전체를 상대 말로 치면
  받는 사람의 말("검찰이라면서 송금하라고요?", 남 이야기 속 "보내")이 근거가 된다. 어휘표 읽기 기준 대리 평가에서
  AI Hub 정상 통화 6,000건 중 `suspected` 가 669건(11.2%)으로 늘었다(아래 표 "단순 제거").

## 결정

1. `transcribe_call` 은 STT 결과를 문장으로 잘라 문장마다 세그먼트 하나를 만든다. 화자 분리 호출·`DIARIZE_*` 설정·
   `speaker_split_failed`·`diarize_model`·`Segment.speaker`·`ClaimReading.other_speaker`/`speaker_confidence` 를 없앤다.
2. 누가 한 말인지는 `ai/src/ai/case/forms.py` 의 정규식이 문장 꼴로 가늠한다. LLM 은 쓰지 않는다.
   - **받는 사람 쪽 말(V-2, `self_side` 로 버림)**: 옮긴 말·되묻기(`~라고요`, `~라면서`, `~라는 거`, `~래요`),
     높임·부탁이 없는 물음("보내야 돼요?", "이름이 뭐예요?"), 부탁 없는 자기 약속·1인칭("제가 보낼게요",
     "제 번호는 …"). 신원 문장은 자기소개 꼴이 아니면 높임 물음("경찰이세요?")도 버린다.
   - 같은 인용이 여러 번 나오면 받는 사람 꼴이 아닌 자리를 쓴다(상대의 "송금하세요" 를 "송금하세요?" 로 되물은 경우).
3. **하한(L-3)에 쓰는 근거는 꼴까지 맞아야 한다**(`Evidence.counts_for_floor`):
   - 기관 주장: 기관 낱말 바로 뒤가 자기소개로 끝남("○○지검 수사관입니다", "검찰청인데", "금감원에서 연락드렸습니다",
     "저희 ○○검찰청…"). 조사가 붙은 언급("경찰이", "검찰에서 수사 중인")은 주의로만 남는다.
   - 지인 주장: "엄마 나야", "나 아들인데", 문장 첫머리 부름말("엄마, 폰 고장 났어"). "우리 아들이" 같은 남 이야기는 아니다.
   - 요구: 듣는 사람에게 해 달라는 꼴("옮기셔야 합니다", "불러 주세요", "입력하시면 됩니다", "어떻게 되세요?",
     "입금해 주면"). 이야기 속 "보내"("시간을 보내면서")는 주의로만 남는다.
   - L-3 = (꼴 맞은 기관 주장 + 꼴 맞은 L-3 요구) 또는 (꼴 맞은 지인 주장 + 꼴 맞은 송금 요구). U-4 는 없어진다.
4. 번호 대조는 받는 사람 쪽 말 꼴이 아닌 문장의 번호만 쓴다.

받는 사람이 검찰·지인이라고 자기를 소개하거나 상대에게 송금을 부탁하는 일은 드물다. 그래서 "자기소개 꼴 + 부탁 꼴"은
누가 말했는지 몰라도 상대 말일 가능성이 높다. 이것이 화자 분리를 대신하는 근거다.

## 결과

대리 평가(어휘표 읽기 → verify → gate, LLM 없음, 2026-10-31). 실제 운영은 LLM 읽기가 먼저이고 어휘표는 폴백이라
운영 수치가 아니다. 대본은 저장소 밖(`D:\voice`, `voice_rag_licensed.jsonl`)이라 집계만 싣는다.

- 표의 숫자는 `suspected` 건수다. 나머지는 대부분 `inconclusive`(주의 포함)라 멈출 행동과 Q1 은 그대로 나간다.
- 정상 통화 오탐은 크게 줄었고, 보이스피싱 `suspected` 비율도 줄었다. 합성 데이터에서 잃은 것은 주로 납치(`kidnapping`)
  유형이다. 납치범은 지인을 내세우지 않고 "따님", "경찰에게 알리면" 처럼 남 이야기만 해서, 이전에는 그 언급이
  하한을 세웠다. 실제 FSS 대본은 통화 중간부터 녹음된 것이 많아 자기소개 문장이 없는 경우가 많다(기관 언급 120건 중
  자기소개 꼴 81건).
- 지인 언급(꼴 없음)도 하한에 쓰면 FSS 32건·합성 20건으로 늘지만 실제 정상 오탐이 128건(2.1%)으로 늘어 채택하지 않았다
  (부탁 꼴 규칙을 다듬기 전 측정).
- 화자 분리 LLM 호출이 없어져 녹음 1건당 평균 약 4.9초(최대 20초 한도)가 줄고, 외부 호출 하나와 그 실패 경로가 사라진다.
- 정규식이 한국어 구어를 다 덮지 못한다. 상대가 자기 요구를 "보내라고 했잖아요" 처럼 옮긴 말로 되풀이하면 그 문장은
  버려진다(대개 앞서 직접 한 요구가 따로 있다). 받는 사람이 "성함이 어떻게 되세요?" 처럼 높임 물음으로 정보를 물으면
  요구로 읽힐 수 있다.
- BE/FE 계약(`contracts/schemas/voice-case-result.schema.json`)은 바뀌지 않는다. `RejectedClaim.reason` 의
  `self_side` 는 "받는 사람 쪽 말 꼴"이라는 뜻으로 계속 쓴다. `TranscriptResult` 의 `speaker_split_failed`·
  `diarize_model` 은 BE 가 아직 쓰지 않아 없앴다.
- 다시 화자 분리를 붙이려면 `forms` 판단 앞에 화자 정보를 넣고 `counts_for_floor` 조건을 그대로 쓰면 된다.
