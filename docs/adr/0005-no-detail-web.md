# ADR 0005 — 상세 웹은 만들지 않고 카카오 카드로 끝낸다

상태: 제안 (2026-09-21, 2026-09-22 범위 갱신)

## 맥락

`frontend/README.md` 는 챗봇 결과의 [자세히 보기]로 넘어오는 Next.js 상세 웹을
전제로 쓰여 있다. 라우트(`/e/[token]`, `/a/[jobId]`, `/routes`), 토큰 교환,
폴링까지 설계돼 있지만 코드는 없다.

`docs/designs/kakao-result-card-prototype.md` 의 개발 채널 검증에서 첫 카드 +
`자세히 보기` 캐러셀 3장(확인한 것 / 확인 못 한 것 / 지금 할 일)으로 현재 범위의
근거를 표현할 수 있음을 확인했다. 사용자 테스트는 하지 않았다.

재설계로 판정이 4상태가 됐고, 콜백 전환(ADR 0003)으로 대기 안내와
콜백 실패 시 결과 재조회 경로도 필요해졌다. 현재 개발 채널에는 R1~R4,
R6, R7 카드가 있으며, R5 대기 카드와 `[결과 확인]` 버튼은 아직 없다.

## 결정

이번 제품 범위에서는 상세 웹을 만들지 않고 카카오 카드 안에서 결과와 근거를
보여준다. FE는 카드의 문구·버튼·흐름을 소유하고, BE는 판정 결과를 카카오
응답으로 조립한다.

- 결과 상태별 카드와 `자세히 보기` 캐러셀을 사용한다.
- 대기 안내와 `[결과 확인]` 버튼은 후속 연결 단계에서 다룬다. 이번 카드 작업의
  완료 항목으로 기록하지 않는다.

`frontend/` 폴더는 지우지 않고 보류로 표시한다.

## 이유

- 카드와 캐러셀로 표현이 된다는 것을 프로토타입에서 이미 봤다. 웹이 더 보여줄
  수 있는 것은 관측 원자료 목록 정도다.
- 웹을 붙이면 토큰 발급·검증, 결과 조회 API, 배포 대상이 하나씩 늘어난다.
  전부 BE 작업을 함께 끌고 온다.
- 카드에서 결과와 근거를 전달하는 흐름을 먼저 검증할 수 있다.
- 사용자가 챗봇 밖으로 나가는 단계가 하나 줄어든다.

## 결과

- `frontend/README.md` 의 웹 전제 설명은 후속 문서 정리에서 보류 상태로 고친다.
  라우트·토큰 설계는 현재 구현하지 않는다.
- 결과 조회 토큰과 웹용 조회 API 는 BE 범위에서 빠진다.
- 캐러셀에 담기지 않는 정보(관측 원자료 전체, 관측 시각·출처 목록)는 사용자에게
  보이지 않는다. 필요하면 캐러셀 장 수를 늘리는 것으로 먼저 해결한다.
- 사용자 테스트에서 "근거를 이해하지 못했다"가 카드 분량 부족 때문으로 나오면
  이 결정을 다시 연다.
- ADR 0003의 콜백 실패 시 조회 폴백 결정은 유지한다. `[결과 확인]` 버튼과
  결과 저장·조회는 후속 작업으로 남으며, 구현 전에는 콜백 실패 시 사용자 재조회가
  불가능하다.
