# ADR 0012: 에이전트 루프는 접었고, AI가 조회를 고르는 실험도 이번에는 하지 않는다

상태: 채택. 루프는 2026-10-27 케이스 분석 설계 v3(`fa4d414`)에서 접었다. 이 기록은 2026-11-11에 남긴다.

설계 v3는 이 결정을 ADR로 옮기기로 했지만(`0006-llm-reads-code-decides`) 그 번호가 다른 ADR에 쓰이면서 기록이 빠졌다. 이 ADR이 그 자리를 채운다.

## 맥락

PRD 3-1은 6칸 루프를 그렸다. 그중 ⑤ "필요한 근거를 더 찾는다"는 모델이 맡는 칸이다.
근거가 부족하면 AI가 허용된 조회 중 하나를 골라 ③으로 되돌아가고, 조회 한도에 닿으면 판단 보류로 끝낸다.
설계 v2는 이 루프를 실제로 설계했다. 도구, 분석 중 질문, 종료 시점을 LLM이 골랐다.

멘토 리뷰가 두 번 있었다.

- PR #24(2026-09-25): 루프를 어디까지 구현했는지 구분해 달라고 했다.
  필요하면 AI가 허용된 조회 중 하나를 고르는 부분부터 만들고, 고정 순서와 근거 확보, 비용, 대기 시간을 비교해 보라고 했다.
- PR #86: 정해진 질문과 선택지에 따른 다음 안내, 링크 유무에 따른 검사, 공식 대조, 재조회는 코드로 하라고 했다.

## 결정

1. **에이전트 루프는 접는다(2026-10-27, 설계 v3).**
   - LLM은 문자와 녹음에서 주장과 요구를 인용과 함께 읽는다.
   - 조사 순서, 결론, 붙일 질문은 코드가 정한다.
2. **PR #24가 제안한 "AI가 조회 하나를 고르는 실험"도 이번 범위(최종 제출)에서 하지 않는다(2026-11-11).** 이유는 남은 시간이다.
3. 문서와 발표에서 이 제품을 "AI가 조사 순서를 정하는 에이전트"로 소개하지 않는다.
   PRD 5-4 피봇 규칙대로 반복 조회 자체를 차별점으로 주장하지 않고, 근거 카드와 공식 경로 안내를 차별점으로 둔다.

지금 순서는 다음과 같다(`main.py`).

1. 링크가 있는 문자
   1. 문자를 읽어 링크와 기관을 뽑는다(`read_message`, LLM).
   2. 링크마다 격리 수집기로 페이지를 모은다.
   3. 문자를 분석한다(`analyze_message_part`).
   4. 공식 주소 대조와 신호로 결과를 만든다(`finalize_analysis`).
   5. 결과가 판단 보류이고 공식 주소가 아니면 문자 게이트(`analyze_message_case`)를 한 번 더 부른다(#89).
2. 링크가 없는 문자는 문자 게이트(`analyze_message_case`)로 바로 간다.
3. 녹음은 녹음 분석으로 간다.

1의 5번째 단계는 근거가 부족할 때 한 번 더 보는 일이지만, 부를지와 무엇을 부를지는 코드가 정한다.

## 이유

설계 v3가 루프를 접은 이유:

- v2에서도 결론은 게이트(코드)가 정했다. LLM이 고르던 조사 경로는 규칙표로 이미 적을 수 있었다.
- LLM에게 남은 갈림길은 질문 시점이었는데, 질문을 결과 아래로 옮기면서(FE D11) 그것도 없어졌다.
- 루프가 없으면 질문 대기, 재개, 만료 상태가 사라져 BE가 단순해진다. 같은 입력이면 같은 조사를 하므로 시험도 쉽다.

이번에 실험을 하지 않는 이유:

- PRD 1-4는 "AI가 조회 순서를 바꾸는 것이 고정 검사보다 낫지 않다면?"을 가장 위험한 곳으로 꼽았다.
  이 질문에 답하려면 같은 사례로 고정 순서와 AI 선택을 비교해야 한다(PRD 5-4). 그 실험을 할 시간이 없다.
- 비교 없이 루프만 넣으면 LLM 호출과 대기 시간만 늘고, 나아졌다고 말할 근거가 없다.
  카카오 첫 응답 5초와 전체 분석 45초 예산(`docs/latency-budget.md`)도 더 빠듯해진다.

## 잃는 것

규칙표에 없는 낯선 경우에 조사 경로를 바꾸는 유연성이다. 규칙이 놓친 경우가 보이면 그 경우를 규칙에 더한다.

## 결과

- PRD의 루프 관련 자리(2-1 ⑥ 행, 2-3 시험 4번, 3-1 ⑤ 칸과 되돌아가는 화살표, 3-2 ① 모델 호출 수)에 "구현하지 않음(ADR 0012)"을 표시한다.
- 2-3 시험 4번 중 시간 예산 부분(첫 응답 5초, 전체 45초에서 취소)은 루프와 별개로 그대로 유효하다.
- 다시 하게 되면 PR #24 제안대로 작게 시작한다.
  AI가 허용된 조회 중 하나를 고르는 부분만 만들고, 같은 사례에서 고정 순서와 비교한다.
  조회 한도와 최종 판정은 그때도 코드가 정한다.
