# HTML 검사기 제한과 DOM 수집 입력 설계

작성일: 2026-09-26

상태: 대화에서 논의한 요구사항과 구현 제안의 문서화. 구현·배포 완료 또는 BE·격리 담당자와의 계약 합의를 뜻하지 않는다. 64단계·100ms 및 서버 자원 배분은 초기 실험값이다.

## 목적과 책임 경계

격리 환경에서 JavaScript 실행 후 관측한 DOM을 메인 서버 AI가 분석하되, 과도한 입력·구조·처리 비용을 제한한다. 중단 시 확인한 자료만 보존하고 미확인 영역을 정상으로 취급하지 않는다.

```text
격리 서버: 페이지 접속 → JS 실행 → 제한된 DOM 자료 추출
    ↓
메인 서버 BE: 응답 수신 상한·인코딩·스키마·수집 상태 검증
    ↓ finalize_analysis(url, message, page, failure=...)
메인 서버 AI: page.info 검사 → 페이지 분석 → env 생성 → result 조립
    ↓
BE: 최종 스키마를 사용자 응답으로 전달
```

AI는 별도 HTTP 수신 서버가 아닌 로컬 Python 패키지다. 격리 서버가 AI 전용 엔드포인트로 직접 전송하는 구조를 추가하지 않는다. BE는 페이지 의미를 판정하지 않고 수집 자료를 AI 함수에 전달한다. 최종 응답에는 원본 DOM 전체가 아니라 분석값과 근거 설명을 반영한다.

## 선행 설계

[종합 판정과 null 설계](2026-09-26-ai-result-and-null-design.md)를 따른다. HTML 제한 보완은 독립적으로 개발할 수 있지만 최종 `env.answer=null`, `result=false` 검증은 해당 변경 적용 후 수행한다.

- 정상 완료·의심 근거 없음: `env.answer=true`.
- 정상 완료·의심 근거 있음: `env.answer=false`.
- 누락·실패·부분 수집·제한 초과: `env.answer=null`, `result=false`.
- 실패 중 확보한 관측과 정상 메시지 결과는 보존한다. 제한 초과를 악성 근거로 설명하지 않는다.
- 정상 미상 `unknown`, 분류 대상 없음 `NONE`(JSON `"없음"`), 실패의 `null`을 구분한다.

## 기존 문서와 정리할 충돌

- [ADR 0002](../../adr/0002-isolation-server.md): BE와 별도 서버, Docker + gVisor 구상. 과거 Observations·격리 서버 자체 분석 설명이 포함돼 있다.
- [인계 문서](../../ai/Revisions-handoff.md): 격리 서버가 `{brand, category, info}`를 반환하고 AI가 HTML을 분석한다.
- [보안 체크리스트](../../security-checklist.md): 원본 HTML 전달 금지. 현재 HTML 입력 계약과 충돌한다.
- [지연 예산](../../latency-budget.md): 격리 12초, 최대 5홉. 예산이지 해당 AWS 사양의 실측 결과가 아니다.

이번 문서는 AI 보완과 전달 요구사항을 제안한다. 원본 HTML 금지 정책을 무단 해제하거나 새 원격 API를 확정하지 않는다. 합의 전에는 제품 연동 문서를 확정된 새 계약으로 덮어쓰지 않는다.

## 격리 서버의 운영 가정과 협의 항목

사용자 제공 사양: BE와 분리된 AWS 서버, 2 vCPU, RAM 4GB, 디스크 50GB.

| 항목 | 초기 제안 | 검증 조건 |
| --- | --- | --- |
| 실행 | 작업별 일회성 Docker + gVisor, Chromium sandbox 활성화 | 비루트 실행·런타임 호환성 확인 |
| 동시 실행 | 1건 | 대기열도 유한하게 제한 |

| 메모리 | 전체 작업 약 2GiB부터 시험 | gVisor·브라우저·공유 메모리·임시 파일 포함 실사용량 측정 |
| 시간 | 기존 12초 예산부터 측정 | 시작·관측·추출·종료 포함, 외부 관리자가 초과 작업 종료 |
| 이동 | 최대 5홉 | 후속 요청도 목적지 정책 적용 |
| 저장 | 임시 자료 작업 후 삭제, 로그 회전 | 디스크 사용량 상한, 다운로드 실행 금지 |

브라우저에 BE 자격증명·Docker 소켓·호스트 공유 디렉터리를 제공하지 않는다. 메타데이터 서비스와 내부망·BE·관리 인터페이스 접근을 실제 연결 경로에서 통제한다. 필요 없는 EC2 메타데이터 엔드포인트는 비활성화한다. 관리상 필요한 AWS 권한은 브라우저 작업과 분리한다.

컨테이너 자원 제한과 네트워크 통제는 수집 담당 범위다. AI의 128KiB 제한이 브라우저의 거대한 DOM 생성이나 BE의 응답 수신 비용을 막는다고 주장하지 않는다.

## 범용 DOM 수집 목록

특정 택배사나 업종 키워드로 수집 대상을 제한하지 않는다. 최종 수집 단위는 개별 태그가 아니라 다음 관계다.

```text
페이지가 주장하는 서비스 → 설명하는 상황 → 요구 행동
→ 요구 정보·조건 → 관련 버튼 → 선언된 목적지
```

| 묶음 | 보존할 요소·속성·문맥 |
| --- | --- |
| 정체성 | title, 주요 제목, 사이트명, 로고 alt |
| 본문 | 문단·목록·표·dl, main/article/section 및 일반 div/span 안의 의미 있는 텍스트 |
| 조건·절차 | 금액, 기한, 수수료, 자격, 환불·이용 조건의 전체 문맥 |
| 입력 | input/textarea/select와 선택지의 표시 문구; type/name/autocomplete/required/readonly/disabled |
| 입력 설명 | label/legend/placeholder/aria-label 및 aria-labelledby/aria-describedby가 참조하는 텍스트 |
| 행동 | 링크·버튼·제출 입력·role=button 등과 주변 설명; 제출 버튼의 표시용 value |
| 관계 | form/fieldset, id/for/form 연결, 폼 밖 입력·제출 버튼의 실제 연결 관계 |
| 목적지 | href/action/formaction/method/formmethod/download; 원래 참조와 기준 URL을 보존해 상대 주소 해석 가능하게 함 |
| 연락 | tel/mailto/메신저 링크와 연락을 요구하는 문맥 |
| 페이지 상태 | 경고·오류·로그인 벽·접근 차단·CAPTCHA·완료 안내 |
| 삽입·시각 콘텐츠 | iframe/img/object/embed의 출처·제목·대체 설명·주변 문맥; 내부 수집 여부 |

전체 JavaScript·CSS와 쿠키·인증 토큰·입력된 개인정보는 기본 전달 대상에서 제외한다. CSS 원문을 제거하더라도 수집기가 실제로 관측한 가시성 정보를 지웠다가 AI가 임의 추측하지 않도록 한다. 원문 인용·주소에도 개인정보가 섞일 수 있으므로 필요한 마스킹 여부와 그 표시를 수집 계약에서 정한다.

`info`는 현재 HTML 문자열이므로 기존 AI 함수에 JSON 문자열을 몰래 넣지 않는다. 관계를 유지한 제한된 HTML로 전달하는 안을 협의한다. 정제·마스킹·잘림이 있으면 원본 전체 DOM과 같은 자료라고 부르지 않는다. AI 근거의 오프셋은 전달된 info에 대한 위치이지 원본 브라우저 DOM의 위치가 아니다.

### 정상·의심 사례 비교 기준

| 사례 | 함께 수집할 내용 |
| --- | --- |
| 배송 | 배송 상태, 주소 수정 이유, 입력·결제·설치 요구 |
| 금융·계정·구독 | 거래·정지·갱신 설명, 인증·결제 항목, 목적지 |
| 공공기관·세금·지원금 | 기관 주장, 신청·납부 근거, 금액·기한·요구 정보 |
| 청첩장·부고·행사 | 행사 내용, 열람 목적, 추가 설치·로그인 요구 |
| 채용·부업 | 업무·보상 조건, 선납·수익 인출 요구, 연락 경로 |
| 쇼핑·중고거래 | 상품·주문·환불 설명, 결제·외부 연락 유도 |
| 예약·병원·학교 | 예약·공지 목적, 필요한 입력, 첨부·연락 경로 |
| 정상 정보 제공 | 본문과 안내를 보존. 행동 요소가 없다는 이유로 수집 실패 처리하지 않음 |

로그인·결제·외부 도메인·기관 로고 존재만으로 악성을 판정하지 않는다. 경고·부정문·인용문을 잘라 실제 요구로 바꾸지 않는다. DOM 존재, 화면 노출, 선언된 제출 주소, 실제 통신·다운로드는 각각 다른 관측이다.

### 별도 메타데이터 요구사항

최초·최종 URL, 이동 경로, 수집 시각, JS 실행 후 DOM이라는 수집 방식, 잘림·차단·실패 이유, iframe/Shadow DOM/이미지 텍스트 수집 범위가 필요하다. 이는 요구 목록이며 이번에 새 HTTP envelope를 정의하지 않는다. 수집하지 못한 영역은 ‘없음’이 아닌 ‘미확인’이다. OCR·자동 입력·클릭·폼 제출·파일 실행은 초기 구현에서 제외한다.

## AI 검사 제한

| 항목 | 설정 | 실패 의미 |
| --- | --- | --- |
| HTML UTF-8 크기 | 131,072 bytes 유지 | INPUT_TOO_LARGE, 파싱하지 않음 |
| 요소 | 2,000개 유지 | PARTIAL_CONTENT |
| 본문 텍스트 | 16,000자 유지 | PARTIAL_CONTENT |
| 노드 깊이 | 초기 64단계, 루트 요소 깊이 1 | PARTIAL_CONTENT |
| 검사 시간 | 초기 0.100초, 파싱·분류·근거 생성 공통 예산 | TIMEOUT |
| 인코딩 불가 문자열 | 기존 계약 오류 ValueError로 명시적 거부 | 수집 정상·악성 판정으로 변환하지 않음 |
| 검사 결과 총량 | 이번 계획 제안: UTF-8 JSON 256KiB | PARTIAL_CONTENT |
| LLM user payload | 이번 계획 제안: UTF-8 JSON 128KiB | INPUT_TOO_LARGE, LLM 호출 생략 |

마지막 두 상한은 대화에서 숫자를 확정하지 않았던 총량 제한을 구현 가능하게 한 제안이다. 일반 페이지·반복 구조 측정 후 조정하며 외부 응답 상한과 혼동하지 않는다. JSON은 `ensure_ascii=False`, `separators=(",", ":")` 기준으로 측정한다. 시스템 프롬프트·SDK envelope 크기나 토큰 수의 상한을 뜻하지 않는다.

인코딩 불가 입력은 현재 FailureCode에 맞는 입력 오류 코드가 없으므로 INVALID_OUTPUT으로 오표기하지 않는다. 공개 함수가 str을 받는 기존 경계 검증처럼 ValueError로 거부하고, BE 수신 오류 매핑은 별도 합의한다. 이는 이번 계획의 구체화 선택이다.

## 중단과 보존

- 문자 수로 명백히 큰 입력을 먼저 거부하여 무제한 인코딩 복사를 피한다.
- 파싱 중단 위치와 원문 범위를 추적한다. 열린 노드 끝을 `len(info)`로 강제 확장하지 않는다.
- entity 디코딩 후 문자 수를 원문 오프셋으로 간주하지 않는다. 텍스트 토큰 중간에서 중단했다면 해당 토큰 전체를 근거 범위에서 제외하는 보수적인 경계를 사용한다.
- 중단 이전에 수집한 노드를 남기되 분류·근거 생성도 남은 시간 예산 안에서만 수행한다.
- 시간 예산을 다 썼다면 복구 분류를 계속하지 않는다. 이미 분류·예산 검증까지 끝난 요소만 반환한다. 파싱 중 시간 초과로 요소 분류를 못 했다면 요소가 비어 있을 수 있다.
- 결과 총량을 초과하면 마지막에 추가한 요소부터 제외하고 PARTIAL_CONTENT를 유지한다. 개별 근거를 임의로 잘라 완전한 요소처럼 반환하지 않는다.
- TIMEOUT은 기존 부분 수집 사유보다 우선한다. 어떤 미완료 사유도 정상 완료로 덮지 않는다.
- 내부 시간 확인은 협력적 중단이다. 정규식·파서 내부 단일 연산까지 100ms 안에 강제 중단한다고 보장하지 않는다. asyncio.wait_for 또는 취소된 스레드가 CPU 작업을 종료한다고 주장하지 않는다.

## 이번 구현 범위와 별도 작업

이번 AI 구현: 입력 크기·인코딩 경계, 깊이·처리 비용·결과 총량 제한, 근거 범위 보존, 부분 실패 통합, 테스트, 범용 수집 요구사항 인계 문서.

별도 합의·구현: 실제 AWS/Docker/gVisor 배포, 브라우저 DOM 추출기, BE 스트리밍 수신과 응답 상한, 원격 스키마, 전체 범용 요소를 AI의 PageElement·프롬프트·분류 체계로 확장하는 작업. 현재 _safe_elements는 목적지 원문 대신 has_href/has_action 등만 전달한다. 수집 항목 목록을 문서화했다고 모든 항목을 AI가 이미 해석한다고 표시하지 않는다.

## 검증 기준

정확한 경계·한 단계 초과, 다바이트 입력, 비정상 Unicode, 깊은 트리, 긴 속성, 반복 폼, 텍스트 중간 잘림, entity, 파싱·분류 시간 초과, payload 초과를 검증한다. 정상 로그인·결제·예약·행사·정보 제공과 명시적 위험 요구를 함께 검사한다. 스크립트 실행·네트워크 접속 없이 기존 pytest와 모의 시계를 사용한다.

실제 서버 도입 시 별도로 1건 순차 부하에서 cold start·RSS·p95·OOM·종료 후 다음 작업 성공을 측정한다. 실제 공격 URL은 자동 단위 테스트에 넣지 않는다.
