# 보이스피싱 분석 AI 파트 설계 (통화 녹음)

- 작성일: 2026-10-28
- 결정: AI 파트(사용자 승인, 2026-10-28 대화)
- 기준 문서: `docs/designs/agent-loop-plan-v3.md`(v3, 이하 "v3 §N"), `docs/designs/voice-phishing-flow.md`(FE 흐름 초안)
- 이 문서와 v3가 다르면 **이 문서가 우선**한다. 이 문서에 없는 것은 v3를 따른다.

## 1. 목적

카카오 챗봇 폴백 블록으로 들어온 통화 녹음을 분석해, 보이스피싱 의심 여부를 **근거와 함께** 낸다.
판정은 코드가 한다. LLM은 대본에서 상대가 누구라고 했고 무엇을 요구했는지를 인용과 함께 읽기만 한다(CLAUDE.md 절대 원칙 1·2).

## 2. 전체 흐름

```
카카오 폴백 블록 → BE: 녹음 주소 판별·내려받기 (BE 담당, 이 문서 범위 밖)
  → AI: STT(whisper-large-v3) → 문장 나누기(화자 분리 없음, ADR 0008)      ← 6.5단계
  → AI: 개인정보 가리기(정규식) → 주장·요구 읽기(Haiku, LLM 1회) ∥ 사례 검색(voice KB)
  → AI: 읽기 검증(코드) → 번호 대조(로컬 KB) → 게이트(코드) → 결과
  → BE: 결과 카드(V1) + Q1 리스트 카드 (BE·FE 담당)
```

## 3. 범위

이번 계획(브랜치 `feature/voice-fishing-ai`)에서 한다.

| 단계 | 내용 |
|---|---|
| 0 | 보이스피싱·정상 통화 데이터 수집 |
| 1 | STT·화자 분리 결과의 반환 형태(타입). 실제 STT 호출은 만들지 않는다 |
| 2 | 주장·요구 읽기(통화 모드) + 어휘표 폴백 |
| 3 | 읽기 검증 V-1~V-8 |
| 4 | 기관 대표번호 KB와 번호 대조 |
| 5 | 사례 검색(voice KB). hit@3 최소 60%, 목표 80% |
| 6 | 게이트(통화 시나리오)와 통화 분석 진입 함수 |

이번 계획에서 하지 않는다.

- **6.5 STT·화자 분리 구현**: 모델별 속도 비교 결과가 나오고 사용자가 모델을 고른 뒤 1단계 타입에 맞춰 구현한다.
- **7 BE 스키마·이슈 초안**: 6.5 뒤에 한다. 이슈 등록은 사용자 확인 후.
- 문자·캡처 경로(v3의 `link_smishing`·`impersonation_no_link`), `apply_answer`, Q2, 페이지 조사. 통화에 필요한 것만 만든다.
- `main.py`·`backend/`·`services/`·`scanner/`·`frontend/`·`infra/`·루트 `tests/` 수정.

| # | 결정 | 이유 |
|---|---|---|

| D2 | 개인정보 가리기는 두 겹이다. **분석 전**: v3 §4 정규식 `mask_pii`(주민·카드·계좌형 숫자열, 전화번호 제외). **저장·외부 전송 전**: 엘리스 PII Masking 모델(`/mask`)을 주입형으로 둔다 | PII Masking 모델은 기관명(`[MASKED_ORGANIZATION]`)과 전화번호(`[MASKED_NUMERIC]`)까지 가려서, 분석 전에 쓰면 기관 사칭 읽기와 번호 대조가 동작하지 않는다 |

| D4 | 대표번호 KB는 공식 누리집에서 모아 로컬 YAML로 둔다. 출처 URL이 있으면 `status: curated` 로 넣는다 | 사용자가 이번 수집분 검수를 면제했다. 속도를 위해 로컬 저장 |
| D5 | 데이터 수집·유형 라벨·합성 대본은 검수 없이 진행한다. 저작권으로 명시적으로 막힌 자료만 뺀다. 레코드마다 출처·라이선스 문구를 남긴다 | 사용자 결정 |
| D6 | 원본 영상·음성과 중간 산출물은 `D:\voice\`, RAG KB 레코드는 프로젝트 `ai/src/ai/kb/voice_cases/`, 평가셋은 `ai/eval/datasets/` | 사용자 결정. KB는 메인 서버가 실행 중에 읽어야 한다 |
| D7 | voice 사례 검색은 스미싱 `search_cases` 와 같은 구조(문자 n-gram TF-IDF)를 쓰고, **KB 폴더와 가중치(파라미터)만 따로** 둔다. 스미싱 검색 동작은 바꾸지 않는다 | 사용자 결정 |

## 6. 성공 기준

- `ai/` 기존 테스트가 모두 통과한다(시작 시 971 passed, 1 skipped).
- 통화 사례 V1·N3·N4·N10·N11·N14가 v3 §9의 기대대로 나온다(가짜 읽기 사용).
- voice 사례 검색 test hit@3 ≥ 60%(목표 80%). 조정 기록이 `ai/eval/reports/` 에 남는다.
- 실제 LLM·네트워크를 부르는 테스트가 없다.
