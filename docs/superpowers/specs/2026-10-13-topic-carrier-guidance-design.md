# 주제 "결제·승인"·"과태료" 추가와 택배사 짧은 이름 인식 설계

- 작성: 2026-10-13
- 상태: 결정 반영 (사용자, 2026-10-13). 자료 2건(NR-0019, NR-0020) 검토 완료 (김수호, 2026-10-14)
- 범위: RAG 멘토 피드백 로드맵 4단계 평가 뒤 남은 결정 D1·D2·D3 ([결정 대기 목록](../../ai/2026-10-13-rag-pending-decisions.md))
- 관련: [업무별 공식 안내 설계](./2026-10-11-norm-guidance-design.md) 5절, `ai/src/ai/taxonomy.py`, `ai/src/ai/kb/norm_rules/`, #69

## 1. 목적

4단계 평가(`ai/eval/reports/2026-10-13-guidance.md`)에서 과태료 문자 58건 중 56건, 해외결제 문자 20건 모두에
확인 방법 안내가 붙지 않았다. 주제(`Topic`)에 두 업무를 알아볼 값이 없어서다. 택배 문자 102건 중 41건은 택배사를
알아보지 못해 택배사별 공식 절차 안내가 붙지 않았다.

지키는 원칙은 [업무별 공식 안내 설계](./2026-10-11-norm-guidance-design.md) 2절과 같다. 주제·택배사는 판정에 쓰지 않고,
LLM 없이 정해진 단어 규칙으로만 정한다.

## 3. 주제 규칙 (`classify_topic`)

본문을 `normalize()` 한 뒤(공백·기호 제거, `[국외발신]`·`[Web발신]` 제거) 단어가 있는지 본다.

| 주제 | 붙는 조건 |
|---|---|
| `과태료` | "과태료·범칙금·무단투기·무단투입·불법투기·불법배출·혼합배출·혼합투기·주정차위반·주정차단속·불법주정차·무인단속·교통법규위반" 중 하나, 또는 "폐기물·쓰레기·음식물·종량제" 와 "위반·부과·무단·불법·투기" 가 함께 있음 |
| `결제·승인` | "카드" 와 "승인" 이 함께 있음, 또는 "해외·국외"(뒤에 "배송·발신" 이 오는 것 제외) 와 "결제·승인·카드·이상거래" 가 함께 있음 |

여러 주제가 함께 걸리면 아래 순서로 고른다. 위의 것이 먼저다.

1. `의료·건강` + `과태료` 만 → `의료·건강`. 검진 안내는 "미수검 시 과태료" 를 덧붙여 쓴다.
2. `과태료` 가 있고 나머지가 택배·쇼핑·금융·결제·승인·공공기관뿐 → `과태료`. 과태료 사칭은 "주소 수정·반송"(택배), "결제 완료"(쇼핑), "계좌"(금융)를 명분으로 섞어 쓴다.
3. `결제·승인` 이 있고 나머지가 쇼핑·택배·금융뿐 → `결제·승인`. 해외결제 사칭은 "결제완료·취소요청"(쇼핑), "배송조회"(택배)를 섞어 쓴다.
4. 그 밖은 기존 규칙 그대로다.

넣지 않은 것과 이유:

- "국제": `[국제발신]` 은 `normalize()` 가 지우지 않고, 과태료·계정 사칭에도 붙는다.
- "해외배송": `[해외배송] … 결제완료` 는 택배로 본다(사용자 결정, 2026-10-11, S-payment-17).
- 통신사·휴대폰 소액결제 승인: 카드가 아니라 NR-0019(카드사 고객센터) 범위 밖이다. 지금처럼 `unknown` 이다.
- 국내 "이상거래 탐지"(승인 없음): 사용자 결정 범위("카드", "승인") 밖이라 넣지 않았다.
- 국민신문고 민원, 법원·검찰 등기, 통행료 미납, 대형폐기물 배출 신고 접수: 과태료 문자가 아니다. 평가 라벨은 `penalty` 지만 주제는 `unknown` 그대로다.

## 4. 택배사 짧은 이름 (`identify_brand`)

정식 이름(`우체국택배`, `한진택배` …)으로 아무 브랜드도 못 찾았고 주제가 `택배` 일 때만 짧은 이름을 본다.

| 브랜드 | 짧은 이름 | 제외 |
|---|---|---|
| 우체국택배 | 우체국 | 우체국예금, 우체국보험 |
| 한진택배 | 한진 | 한진해운, 한진관광, 한진칼 |
| 롯데택배 | 롯데 | 롯데카드·몰·홈쇼핑·마트·온·백화점·손해보험·캐피탈 |
| 로젠택배 | 로젠 | — |

- 정식 이름으로 알아본 브랜드는 바꾸지 않는다. "[우체국] 쿠팡 상품 배송" 은 그대로 쿠팡이다.
- 짧은 이름이 둘 이상 걸리면 기존 규칙대로 `unknown` 이다.
- `CJ우체국` 같은 혼합 명칭은 기존 `_NON_BRANDS` 가 먼저 걸러 `unknown` 이다.
- "대한통운"(CJ대한통운의 짧은 이름)은 결정 범위 밖이라 넣지 않았다.

## 5. 자료

| 자료 | 바뀐 것 | 상태 |
|---|---|---|
| NR-0019 카드사 고객센터 직접 확인 | `match` 를 `{category: 금융, doubts: 전화 응대}` → `{category: 결제·승인}` | curated (김수호, 2026-10-14) |
| NR-0020 과태료 확인 경로 (새 자료) | 과태료 주제 전체에 거는 확인 경로(경찰서 교통 과태료는 이파인·공식 앱, 시·군 과태료는 시·군 대표번호). `match: {category: 과태료}`. 발췌문 10개 원문 대조 완료 | curated (김수호, 2026-10-14) |
| NR-0008 교통 과태료 확인 경로 | 근거 발췌문 하나가 이파인 누리집 HTML 주석 안에 있어 화면에 보이지 않았다. 그 발췌문과 그것에 기댄 위택스·서울시 구절을 뺐다 | draft, `match` 없음 |

NR-0019 의 적용 범위(`applies_to`)는 카드사 전체다. 국내 카드 승인 문자에 붙는 것은 적용 범위 안이다.

과태료는 전국 단위 확인 경로 자료가 이미 둘 있었다(NR-0004 쓰레기 과태료 → 시·군 대표번호, NR-0008 경찰서 교통 과태료 → 이파인).
결정 대기 목록의 "과태료 자료는 모두 지역 자료"는 틀렸다. 다만 둘 다 적용 범위가 과태료 일부라 `{category: 과태료}` 에 걸면
"적용 범위보다 넓게 걸지 않는다"(양식, 검토 기준 6)에 어긋난다. 그래서 두 경로를 과태료 전체를 범위로 하는 NR-0020 으로 모으고,
NR-0004·NR-0008 에는 `match` 를 달지 않았다. 위택스(지방세)는 과태료 주제로 잡히지 않고 화면에 보이는 전국 단위 근거가 없어 뺐다.

## 6. 결과 형식 영향

- `Topic` 값이 8개에서 10개가 된다. `message.category`·`env.category` 에 `결제·승인`·`과태료` 가 나올 수 있다.
  값 목록은 `docs/ai-be-final-result-schema.md` 에 더했다. `docs/scheme.md` 는 `types.py` 를 따른다고만 적혀 있어 고치지 않았다.
- BE·FE 코드는 `category` 값을 나열하거나 검사하지 않는다(저장소 검색, 2026-10-13). 카드 코드(`services/result_card_*.py`)도 읽지 않는다.
  그래도 값이 늘었다는 것을 알리는 이슈를 연다.
- 페이지 분석 LLM 이 낸 분야도 `Topic` 값과 정확히 같을 때만 받으므로 새 값이 그대로 통한다. 프롬프트는 바꾸지 않았다.
- `compare_claims()` 의 주제 어긋남은 새 값끼리도 같은 방식으로 센다. 판정에는 쓰지 않는다.
