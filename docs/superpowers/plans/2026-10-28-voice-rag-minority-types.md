## Task 5: 확인된 신원 주장으로 사례 유형 우선

- 검증(`verify_call`)을 통과한 신원 주장 종류(`IdentityKind.ACQUAINTANCE` → 가족 사칭·납치, `COMPANY` → 기타 사칭·계좌 모집, `INSTITUTION` → 기관 사칭·대출 빙자 등; 정확한 대응표는 KB 레코드를 보고 정한다)로 검색 결과 순위를 결정적으로 조정한다. 방식(필터 vs 가점)은 dev 로 고른다. 주장이 없거나 읽기가 lexicon 폴백이어도 같은 규칙.
- 평가: 평가 질의마다 `ai.case.lexicon.read_with_lexicon`(결정적; 신원 주장을 내지 않으면 신원 어휘 판별 함수를 같은 모듈에 추가해 운영·평가가 함께 쓴다)로 신원 종류를 얻어 같은 규칙을 적용한다. LLM 은 부르지 않는다.
- 채택 기준은 Task 4 와 같다. 판정(`decide_call`)은 바꾸지 않는다.
- 테스트: 가족 주장 → 가족 사례가 앞에, 주장 없음 → 기존 순위와 같음.
## 리서치 반영 (2026-10-28, 사용자 요청 "채용할 방식이 있으면 적용해 성능 개선")

조사한 방식과 채택 여부:
- **지도 학습 이진 분류(보이스피싱 vs 정상)**: KorCCVi 벤치마크에서 TF-IDF + 로지스틱 회귀 정확도 약 97%, KoBERT 99.6% (KIPS Trans. 11(10):437-446, github selfcontrol7/Korean_Voice_Phishing_Detection). 지금 검색은 정상 사례 없이 유사도 하나로 붙일지 정한다 → 정상까지 학습한 **가벼운 선형 분류기**를 "사례를 붙일지" 결정하는 관문으로 채택. KoBERT 는 torch 의존성·지연 때문에 채택하지 않는다.
- **키워드 + 대화 흐름(단계) 종합**: SKT 에이닷 전화(의심 키워드·대화 흐름 종합, 의심/위험 2단계), 후후(축적 사례와 발화 패턴·문맥 대조), Shen et al. CHI EA 2025(통화 사기 모델링), SCRIPTMIND(범죄 스크립트 단계). → 신원 주장·구실·급박/비밀 유지·요구 같은 **수법 단계 신호**(기존 lexicon)를 관문 특징으로 채택.
- **불확실 선택지(UNCERTAIN)로 오탐 줄이기**(Shen et al.): 우리 결론에는 이미 `inconclusive` 가 있다. 사례 첨부는 관문 점수가 애매하면 붙이지 않는 쪽(보수적)으로 둔다.
- **KT: 초반 150음절 분석**: 앞서 `--query-head` 로 쟀고 이득 없음(조정 기록 #14·#15). 채택 안 함.
- **역번역·SMOTE 증강**: 한국어 사례만 쓰기로 해 채택 안 함.

## Task 6: 사례 첨부 관문(보이스피싱 같음 점수) — 선형 분류기 + 수법 단계 신호

- 학습(오프라인, `ai/eval/voice_gate_train.py`): 문자 n-gram(2~4) + 어절 TF-IDF → 로지스틱 회귀, 여기에 lexicon 수법 단계 신호(신원 주장 종류, 요구 종류, 급박·비밀 유지·끊지 말라 같은 blocker, 구실) 몇 개를 수치 특징으로 더한다. sklearn 은 학습 스크립트에서만 쓴다(시스템 Python 또는 eval 전용 의존성). 운영 코드에는 새 의존성을 더하지 않는다.
- 내보내기: 계수와 어휘를 `ai/src/ai/kb/voice_gate.json`(크기 2MB 이하, 어휘 상한)으로 저장하고, 운영 추론은 순수 Python(`ai/src/ai/kb/gate_model.py` 등)으로 한다. 같은 입력에 sklearn 과 같은 점수(소수 6자리)를 내는지 테스트한다.
- 학습 데이터(저장소에 둘 수 있는 것만으로 **배포용 가중치**를 만든다): 양성 = voice KB 의 보이스피싱 레코드(KB 몫만), 음성 = 합성 정상 대본 중 **학습 전용 group**. 지금 합성 정상 group 은 모두 dev/test 라서, 정상 유형마다 새 틀 12개 이상을 학습 전용으로 더 만든다(Task 1 방식, 한국어, 검수 없음, `split: train`, 프로젝트 `ai/eval/datasets/voice_gate_train.jsonl`). dev/test 질의는 학습에 쓰지 않는다.
- 비교 실험(로컬 전용, 배포 안 함): 실제 정상(D: normal_real) 의 dev 일부를 학습에 더한 가중치. dev 를 group 기준 둘로 나눠 한쪽은 학습, 다른 쪽으로 잰다. 결과만 리포트에 남기고, 이 가중치를 배포할지는 사용자 결정으로 넘긴다(AI Hub 결과물 배포 조건 미확인).
- 관문 적용: `search_voice_cases` 결과를 붙이기 전에 관문 점수 ≥ 기준이면 붙이고 아니면 `similar_cases` 를 비운다. 판정(`decide_call`)·결론·근거는 바꾸지 않는다. 관문 실패(예외)는 사례 미첨부 + `unchecked`(기존 similar_cases 실패 처리와 같게).
- 대조 방식(옛 Task 6): 정상 레코드를 KB 에 넣고 top-k 다수결로 막는 방식도 같은 dev 로 재서 관문과 비교한다(정상 레코드는 학습 전용 합성만). 더 나은 쪽 하나만 채택한다(둘 다 채택도 가능, 근거를 리포트에).
- 선택 기준: dev(실제 정상 포함, qa_written 제외) 정상 부착률 ≤ 5% 에서 hit@3 과 유형 평균 hit@3 이 가장 높은 설정. 유사도 기준값과 관문 기준을 함께 고른다.
- 지연: 관문 추론 p95 를 재서 사례 검색 예산(1초) 안인지 확인한다.
