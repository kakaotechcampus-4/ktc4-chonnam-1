# Revisions 연동 작업 인계

기준: [Revisions.md](./Revisions.md). 확정한 계약과 타 파트의 작업을 기록한다. AI 공개 함수는 구현돼 있으며, 이 문서는 BE·FE·격리 환경의 연동 완료를 뜻하지 않는다. 코드 변경 범위는 `ai/` 내부이며 타 파트 코드는 각 담당자가 수정한다. BE가 작성할 구문은 [Python 연동 코드](../ai-be-python-integration.md)를 참고한다.

## 확정된 계약

- BE는 urlscan의 악성 위험도 점수를 임계값 `T`와 비교한다. `score <= T`이면 `official=true`, `score > T`이면 `official=false`다. 임계값 결정과 점수 가공은 BE 책임이다.
- 현재 `official`은 점수 기준 통과 여부다. 화이트리스트 대조나 실제 공식 도메인 확인 결과로 설명하지 않는다.
- 유효한 boolean을 전달받은 AI의 최종 결과는 `result = url.official`이다. 메시지·격리 환경 분석이나 LLM은 이를 뒤집지 않는다.
- `result=false`는 의심이며 악성·스미싱 확정을 의미하지 않는다.
- `official=true`이면 `result=true`로 조기 반환한다. `message`, `env`, 각각의 `details` 객체와 모든 키를 유지하고 말단 값 10개를 `null`로 반환한다.
- `official=false`이면 두 분석 결과로 근거를 보충한다. 둘 다 안전으로 분석되어도 최종 결과는 `false`다.
- 분석 실패·페이지 접속 실패·타임아웃 시 해당 분석의 `answer=false`로 의심 처리한다. `details.reason`에 확인된 실패 사유를 기록하고, 확보한 필드는 유지하며 식별하지 못한 정형 값은 `unknown`으로 표현한다. `answer=null`은 조기 반환에만 사용한다.
- `message.details.doubt`는 문자에 명시된 접속 목적·요구, `env.details.doubt`는 페이지에서 확인한 요소·요구 내용이다. JSON 구조는 유지하고 두 필드의 허용 목록·근거 검증·대표값 선택을 분리한다.

## BE 담당

1. 원본 메시지에서 URL과 URL을 제거한 본문을 분리하고, 본문을 AI에 전달한다.
2. urlscan의 사용할 score 필드, 임계값 및 경계값 처리를 정한다. 누락·조회 실패·범위 초과를 정상 점수로 간주하지 않도록 별도 처리 계약을 확정한다.
3. `final_url`, `domain`, `official`을 AI 입력 타입에 맞게 전달한다. AI 내부에 urlscan 조회나 임계값 비교를 넣지 않는다.
4. URL 분석·메시지 분석·격리 환경 수집을 병렬로 시작하고, `official=true`이면 불필요해진 작업을 취소한다. 외부 요청과 태스크의 생성·취소는 BE 오케스트레이션에서 담당한다.
5. `official=false`이면 확보한 문자 분석 결과·격리 수집 자료·실패 코드를 `await finalize_analysis(...)`에 전달한다. AI가 페이지 분석과 결과 조립을 끝내고 전체 응답을 반환한다. 정해진 시간 예산에는 이 페이지 분석 시간도 포함한다. 콜백·저장·결과 조회는 BE에서 담당한다.
6. AI의 `null` 필드를 제거하지 않고 FE로 전달한다. `message.answer`와 `env.answer`가 최종 `result`와 다를 수 있음을 반영한다.
7. 접속 실패·타임아웃 등을 `failure: FailureCode | None`으로 전달하고 부분 자료가 있으면 page도 함께 전달한다. 빈 HTML만으로 실패 원인을 추정하게 하지 않는다. 수집기의 원격 응답을 이 Python 인자로 옮기는 방법은 BE·수집기 연동에서 확정한다.

## 격리 환경 담당

1. 페이지 접속과 렌더링을 수행하고 `brand`, `category`, `info` 형태로 반환한다. `info`는 수집한 HTML이다.
2. 수집 실패와 빈 페이지, 부분 수집을 구별할 방법을 AI·BE와 합의한다. 현재 세 필드만으로는 실패 상태를 명시하기 어렵다.
3. HTML 크기 제한과 수집 시간 제한, 취소 처리를 합의한다. AI 파트는 전달받은 HTML을 분석하며 페이지 접속·실행을 맡지 않는다.
4. HTML 요소의 존재와 실제 화면 노출·다운로드·폼 제출 관측을 구분한다. 실행 관측을 추가 전달하려면 별도 입력 계약을 합의하며, HTML만 전달한 상태에서 실제 동작까지 확인했다고 해석하지 않는다.

## FE 및 사용자 응답 가공 담당

1. `result=false`를 '의심'으로 표시한다. '악성 확정', '스미싱 확정'이라는 문구로 바꾸지 않는다.
2. 점수 기준 미통과를 '공식 도메인이 아님을 확인함'으로 표현하지 않는다.
3. 조기 반환의 `null`은 분석 결과 미제공으로 표시한다. 안전·의심·오류라는 분석 결과를 임의로 채우지 않는다.
4. 최종 결과와 메시지·페이지별 분석 결과를 구분해서 표시한다.
5. `answer=false`에는 의심 근거 발견뿐 아니라 확인 실패에 따른 의심 처리도 포함된다. `details.reason`을 함께 표시하여 원인을 구별한다. 접속 실패만으로 분석 회피나 악성을 확정했다고 표시하지 않는다.
6. 문자에는 '접속 목적·요구', 페이지에는 '확인한 페이지 요소·요구'라는 의미로 `doubt`를 표시한다. 두 값이 다르다는 이유만으로 악성 확정이나 사칭 확인으로 표시하지 않는다.

## AI 공개 함수와 연동 경계

기존 구현 배경은 [AI 구현 계획](./2026-09-23-revisions-implementation-plan.md), 최종 호출 통합은 [후속 계획](../superpowers/plans/2026-09-23-ai-finalize-be-integration.md)에 있다. 아래는 현재 코드에서 사용할 수 있는 Python API이며 BE·FE 서비스 배포를 뜻하지 않는다. 새 연동은 문자 분석과 최종 함수 호출을 기본 경로로 사용한다.

| AI 공개 함수 | BE의 입력 | 반환·역할 |
|---|---|---|
| `analyze_message_part(text, *, client=None, model=None)` | URL을 제거한 본문 | async `MessagePart` |
| `finalize_analysis(url, message=None, page=None, *, failure=None, client=None, model=None)` | 검증한 URL·앞선 문자 결과·격리 자료·실패 코드 | async `AnalysisResponse`, 페이지 분석과 조립을 내부 수행 |
| `analyze_environment_part(page, *, failure=None, client=None, model=None)` | `IsolatedPage(brand, category, info)` 또는 수집 실패 | async `EnvironmentPart` |
| `assemble_analysis(url, message=None, env=None)` | 검증된 `UrlAnalysis`와 부분 결과 | 순수 함수, `AnalysisResponse` |

`analyze_environment_part()`와 `assemble_analysis()`는 개별 사용과 기존 호출 호환성을 위해 유지한다. BE가 새 연동에서 페이지 분석과 조립을 각각 호출할 필요는 없다. `client`와 `model`은 테스트·설정 주입용 선택 인자다. BE가 LLM 호출을 직접 구현할 필요는 없다.

### BE 작업 목록

- [ ] URL 결과를 `UrlAnalysis.model_validate()`로 검증한다. `official` 누락, 문자열 `"false"`, 숫자 `0/1`, null은 거부한다. 입력 오류는 사용자 응답으로 처리하되 AI가 임의의 `official`이나 정상 분석 결과를 만들어내게 하지 않는다.
- [ ] 성공한 페이지는 기존 세 필드 `{brand, category, info}`로 전달한다. 수집 실패는 `page=None, failure=FailureCode.COLLECTION_FAILED`, 시간 초과는 `failure=FailureCode.TIMEOUT`으로 전달한다. 부분 자료가 있으면 page도 함께 넘긴다. 이 Python 호출 계약을 원격 JSON으로 옮길 경우 별도 envelope를 정한다.
- [ ] 본문·URL 분리와 개인정보 마스킹을 유지한다. AI의 근거는 실제 전달받은 본문을 기준으로 하므로 전달 전후 텍스트가 달라지지 않도록 관리한다.
- [ ] 시작 시 기존 `ai.kb.search.load_cases()`로 검색 캐시를 준비한다. 메시지 분석은 추출 1.5초와 검색 50ms를 병렬 실행한 뒤 신호 제안 2.0초를 수행한다. AI의 검색 timeout이 로컬 작업 스레드를 강제 종료하지는 않으므로 요청량 제한은 BE에서 관리한다.
- [ ] URL 분석·메시지 분석·격리 수집을 병렬 관리한다. `official=true`가 도착하면 두 분석 결과를 기다리지 않고 `await finalize_analysis(url)`을 사용한다. 불필요 작업을 취소·정리하고 늦게 완료된 결과가 저장된 응답을 덮어쓰지 않게 한다.
- [ ] urlscan 점수 도착 전에는 이 규칙으로 안전을 반환하지 않는다. 여기서 '조기 반환'은 boolean 도착 이후이며, 기존 화이트리스트 즉답과 같은 시점이라는 뜻이 아니다.
- [ ] `official=false`이면 확보한 문자 결과와 격리 수집 자료를 `await finalize_analysis(url, message, page, failure=...)`에 전달한다. AI가 페이지 분석 후 전체 결과를 돌려준다. 알고 있는 수집 실패를 자료 누락으로 숨기지 않고 failure로 전달한다. 이미 완료한 문자 결과를 버리거나 다시 분석하지 않는다.
- [ ] `response.model_dump(mode="json")`으로 직렬화한다. `exclude_none=True`나 `exclude_unset=True`로 조기 반환 키를 제거하지 않는다.
- [ ] 기존 AI 공개 함수는 호환용으로 남는다. 새 워크플로우는 `ai.pipeline`의 위 함수로 전환하고 기존 `decide(DomainCheck, Observations, ...)` 판정을 새 `result`와 섞지 않는다. 기존 `DomainMatch.OFFICIAL`을 점수 기반 `official`로 자동 변환하지 않는다.
- [ ] 콜백·캐시·저장·조회 폴백과 외부 deadline을 기존 BE 영역에서 구현·검증한다.

### 격리 환경 작업 목록

- [ ] 수집 성공, 접속 실패, 시간 초과, 부분 수집을 BE가 식별할 수 있게 전달한다. 페이지 내용이 비었는지와 수집 자체가 실패했는지를 구분한다.
- [ ] AI 초기 상한인 HTML UTF-8 131,072바이트, 분석 요소 2,000개, 페이지 텍스트 16,000자를 검토한다. 상한에 걸린 자료는 정상 완전 분석으로 취급되지 않으며, 임의 절단한 HTML을 완전 자료로 표시하지 않는다.
- [ ] HTML 외에 실제 화면 표시·다운로드·폼 제출 관측이 필요하면 별도 구조를 합의한다. 현재 AI는 그런 실행 사실을 추론하지 않는다.
- [ ] 실제 페이지의 정상 로그인·결제·앱 다운로드·주소 입력·조회 화면 사례를 마련해 `EnvDoubt` 후보를 검증한다. 합성 HTML 테스트 통과를 실제 페이지 정확도 검증으로 대체하지 않는다.

### FE 및 응답 가공 작업 목록

- [ ] `result=false`를 '의심'으로 표시하고, 개별 answer와 전체 결과를 구분한다. 두 answer가 true여도 result false일 수 있다.
- [ ] 문자 `doubt`와 페이지 `doubt`의 별도 허용 목록을 적용한다. 공통 위험도 순위나 동일한 문구 변환 테이블로 합치지 않는다.
- [ ] `없음`, `unknown`, 조기 반환의 `null`을 구분한다. 실패의 `answer=false`에는 실제 실패 사유를 함께 표시한다.
- [ ] reason은 평문으로 렌더링하고 입력에서 인용된 문구를 HTML로 실행하지 않는다. 원본 HTML을 AI 설명 대신 사용자 화면에 그대로 삽입하지 않는다.
- [ ] 'HTML에서 링크/폼 확인'을 '실제 다운로드/개인정보 전송 확인'으로 바꾸지 않는다.

### 공통 검토 사항

- [ ] 구현 계획의 개별 answer 규칙을 확인한다. 완료된 분석에 검증된 의심 신호가 없을 때만 해당 범위에서 true이며, 일반 로그인 폼·결제 UI나 두 분류의 차이만으로 악성을 확정하지 않는다.
- [ ] 새 페이지 LLM 예산 2.0초와 입력 상한, 초기 브랜드·분야 후보를 연동 시 검토한다. 이 값들은 구현 계획의 초기 선택이다.
- [ ] `CLAUDE.md`·기존 지연 예산·ADR에 남은 화이트리스트 기준과 새 점수 기준의 차이를 저장소 정책 담당자가 정리한다. 이 AI 코드 작업에서 해당 기존 문서는 수정하지 않는다.

## 정형값 연동 검토안

문자·페이지 `doubt`의 분리 방향은 합의하여 반영했다. 브랜드·분야 목록은 검토안이며 페이지 목록은 실제 HTML 사례 검증이 필요한 설계 후보다. 아래 목록이 운영 코드에 적용되었다는 뜻은 아니다.

- JSON의 `brand`, `category`, `doubt`는 한글 표준명과 `unknown`의 닫힌 목록을 제안한다. 초기 브랜드 후보는 23개와 `unknown`, 분야 후보는 7개와 `unknown`이다. 전체 후보와 근거 사례는 [Revisions.md](./Revisions.md)에 있다.
- `category`는 분야다. `message.details.doubt`는 문자에서 명시한 목적·요구로 `MessageDoubt`를 사용하고, `env.details.doubt`는 페이지 요소·요구로 `EnvDoubt`를 사용한다. 두 목록을 공통 Enum으로 취급하지 않는다. 기존 AI 내부 `CategoryCode` 값과도 구분한다.
- `brand`는 실제 발신 확인 결과가 아니라 현재 입력에서 추출한 주장 명칭이다. 서로 다른 회사·기관·서비스를 임의로 합치지 않는다.
- `message.details.doubt=없음`은 문자 분석 결과 명시적 행동 요구가 없는 경우다. `env.details.doubt=없음`은 제공된 페이지 자료 분석 결과 분류 대상 요소·요구가 없는 경우다. `unknown`은 식별 불가, `null`은 조기 반환이다. 세 값을 같은 빈 값으로 취급하지 않는다.
- 문자용 목록은 배송 조회·주소 확인·앱 설치 등 13개와 `없음`, `unknown`이다. 페이지용 목록은 앱 다운로드 링크·로그인·인증 입력폼·결제 요청 요소·개인정보 입력폼·주소 입력폼·배송 조회 요소·사진·문서 열람 요소의 7개와 `없음`, `unknown`이다.
- 페이지 목록은 HTML 분석용 설계 후보이며 문자 사례에서 검증된 라벨이 아니다. 앱 다운로드 링크 존재를 실제 다운로드·설치로 표시하지 않는다.
- `doubt`에는 일반적인 조회 목적·페이지 요소도 포함된다. FE가 이 값 자체를 '악성 행동 발견'으로 변환하지 않도록 한다. 대표값 하나가 표시되어도 같은 출처에서 확인한 다른 후보는 `details.reason`에 포함될 수 있다.
- 대표값은 출처별로 구체적인 명시 요구·관측 요소를 우선하며, 독립적인 후보가 여러 개면 문자 원문·HTML 소스 순서를 따른다. 공통 위험도 우선순위를 적용하지 않는다.
- 메시지·페이지별 분류 결과가 서로 다를 수 있다. 한쪽의 브랜드·분야·`doubt`·근거를 다른 쪽으로 덮어쓰지 않는다. 배송 조회 문자와 로그인 폼 페이지의 차이는 설명하되 그 차이만으로 악성을 확정하지 않는다.

## 연동 검증 기준

- BE의 임계값과 같은 점수는 `true`, 초과 점수는 `false`다.
- 조기 반환에서 두 분석 객체의 구조와 말단 `null` 10개를 보존한다.
- `official=false`이며 두 분석의 `answer=true`여도 `result=false`다.
- 분석 실패 시 해당 분석의 `answer=false`, 최종 `result=false`를 유지하고 실제 실패 사유를 제공한다. 실패만으로 악성·분석 회피를 확정하지 않는다.
- 개별 분석 실패가 이미 발생했어도 `official=true`인 조기 반환에서는 두 분석의 말단 값을 모두 `null`로 반환한다.
- 결과 표시에서 의심과 악성 확정을 구별한다.
- 문자에만 있는 앱 설치 요구를 페이지의 다운로드 링크 관측으로 복사하지 않으며, 페이지에만 있는 요소도 문자 요구로 복사하지 않는다.
- 문자 목적과 페이지 요소가 다른 결과를 보존하고, 차이만으로 악성 확정 문구를 생성하지 않는다.
- HTML만 제공한 입력의 설명은 요소 존재 범위를 넘어서 실제 화면 노출·다운로드·폼 제출을 확인했다고 주장하지 않는다.
