## D1. 주제(Topic)에 "결제·승인"·"과태료"를 더할지

### 배경

확인 방법 안내(`find_guidance()`)는 문자의 주제·브랜드·요구 행동 같은 정해진 값으로 자료를 고른다. 지금 주제는
`택배·쇼핑·금융·공공기관·의료·건강·보안·선물·이벤트·unknown` 여덟 가지라(`ai/src/ai/types.py` 의 `Topic`),
과태료 문자와 해외결제 문자를 알아볼 값이 없다. 3단계 설계에서 "평가로 놓치는 비율을 잰 뒤 정한다"고 미뤘다
(`docs/superpowers/specs/2026-10-11-norm-guidance-design.md` 5절).

### 근거

| 정답 업무 | 행 | 맞게 안내 | 빠짐 | 고정 규칙이 붙인 주제 |
|---|---|---|---|---|
| 과태료 | 58 | 0 | 56 (96.6%) | unknown 50, 쇼핑 5, 택배 2, 금융 1 |
| 해외결제 | 20 | 0 | 20 (100%) | unknown 16, 쇼핑 4 |

- 주제 규칙(`ai/src/ai/taxonomy.py` 의 `classify_topic`)에 "과태료"·"카드 승인"·"해외결제" 같은 단어가 없다. 금융은 "은행·급여·계좌·증권·인출"로만 정해진다.
- 과태료 문자 2건(`K-same_pretext-penalty-01`·`-02`)은 "주소 수정"·"반송" 때문에 주제가 택배로 나와 택배 안내(NR-0015)가 엉뚱하게 붙었다.

### 선택지

| | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A** | 두 값을 모두 더한다 | 두 업무 모두 안내를 붙일 길이 생긴다. 과태료 문자가 택배로 잘못 읽히는 것도 막을 수 있다 | 결과 형식이 바뀐다(아래 범위) |
| B | "결제·승인"만 더한다 | 바로 붙일 자료(NR-0019)가 있다 | 과태료는 그대로 놓친다 |
| C | 주제는 두고 "업무" 칸을 새로 만든다 | 주제와 업무를 따로 쓸 수 있다 | 결과 형식 변경이 더 크다. 지금은 업무 3개라 이득이 적다 |
| D | 바꾸지 않는다 | 변경 없음 | 과태료·해외결제 문자에는 확인 방법을 안내하지 못한다 |

### 추천: A

### A 를 고르면 바뀌는 범위

- AI: `Topic` 값 2개, `classify_topic` 규칙(과태료가 택배보다 먼저 정해지도록), 관련 테스트. 페이지 분석 LLM(`ai/src/ai/llm/page.py`)이 내는 주제도 `Topic` 값만 받으므로 함께 영향을 받는다.
- 문서·계약: `docs/scheme.md` 의 `category` 값. BE·FE 이슈를 새로 연다. 지금 카드 코드(`services/result_card_*.py`)는 `category` 를 읽지 않아 화면 영향은 작다.
- 자료: 과태료 자료 NR-0002~0009 는 모두 특정 지역 자료라 주제만 더해서는 붙일 안내가 없다. **지역을 가리지 않는 확인 경로 자료**
  (예: "고지서·위택스·이파인에서 직접 조회") 를 새로 써서 검수를 받아야 한다.
- 평가: 바꾼 뒤 `guidance_eval.py` 를 다시 돌려 빠짐 비율과 정상 문자 오부착을 비교한다.

## D2. NR-0019(카드사 고객센터 직접 확인)의 적용 조건

### 배경

NR-0019 는 "카드사 고객센터에 직접 전화해 확인하라"는 해외결제 업무의 확인 경로 자료다. 지금 조건은
`{category: 금융, doubts: 전화 응대}` 이고 검토를 미뤄 draft 상태다.

### 근거

- draft 를 정식으로 쳐도 이 조건에 맞는 평가 문자는 **0건**이다(리포트 ⑤).
- 해외결제 문자는 주제가 금융으로 나오지 않는다(D1 표). 요구 행동 "전화 응대"도 고정 규칙으로는 거의 잡히지 않는다.

### 선택지

| | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A** | D1 에서 "결제·승인"을 더한 뒤 조건을 `{category: 결제·승인}` 으로 바꾸고 검토해 정식으로 올린다 | 해외결제 문자에 바로 붙는다 | D1 이 먼저 정해져야 한다 |
| B | 조건을 `{category: 금융}` 으로 넓힌다 | 지금 값으로 바로 할 수 있다 | 은행 대출·계좌 문자에도 카드사 안내가 붙는다. 금융으로 나오는 해외결제 문자도 없어 효과가 없다 |
| C | draft 로 둔다 | 변경 없음 | 해외결제 문자에 안내가 계속 없다 |

### 추천: A (D1 을 A 또는 B 로 정한 경우). D1 이 D 면 C.

## D3. 택배사 인식 보완

### 배경

택배사별 공식 절차 자료(NR-0011 우체국, NR-0012 한진, NR-0013 롯데, NR-0014 로젠)는 브랜드가 정확히 알아봐져야 붙는다.
브랜드는 `ai/src/ai/taxonomy.py` 의 별칭 목록으로 정하는데, 우체국은 "우체국택배"·"우체국물류"만 있다.

### 근거

- 택배 문자 102건 중 41건은 택배사를 알아보지 못했다(5개사 44 · 모름 41 · 기타 업체 17).
- "[우체국]"처럼 쓴 문자는 브랜드가 모름이 되어 NR-0011 이 붙지 않는다.
- 택배 고객센터 직접 확인(NR-0015)은 택배 주제면 택배사를 몰라도 붙는다. 그래서 놓치는 것은 택배사별 절차 안내뿐이다.

### 선택지

| | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A** | 주제가 택배일 때만 "우체국"을 우체국택배로 알아본다 | 우체국 택배 문자에 절차 안내가 붙는다 | 규칙이 주제에 기대 조금 복잡해진다 |
| B | "우체국"을 항상 우체국택배로 알아본다 | 가장 단순하다 | 우체국 예금·보험 사칭 문자까지 택배로 잘못 알아본다 |
| C | 그대로 둔다 | 변경 없음 | 41건 중 일부가 계속 택배사를 모른다 |

### 추천: A

바꾼 뒤 택배사 모름 수와 정상 문자 오부착(지금 28건, 4.9%)을 다시 잰다. 다른 택배사 별칭(예: "한진"만 쓴 문자)도 같은 방식으로 볼지 함께 정한다.
