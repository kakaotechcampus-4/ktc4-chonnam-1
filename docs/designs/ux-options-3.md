# FE UI/UX 3안 비교와 웹 필요성 검증 설계

- 작성일: 2026-09-17
- 상태: **검토 요청(Draft)**
- 배경: 멘토 피드백 — "최소 세 가지 UI/UX 안을 비교하고, 스케치를 소수 사용자에게 보여주는 실험을 하라. **웹이 필요한지는 챗봇에서 전달하기 어려웠던 정보가 무엇인지 관찰하며 판단하라.**"
- 선행 문서: `docs/designs/smishing-message-intake-ux.md` (흐름·12개 상태)

## 0. 이 문서가 답하려는 질문

`frontend/`는 이미 "2차 웹(Next.js)"을 전제로 폴더와 역할이 확정돼 있다.
**그 전제에는 근거가 없다.** 이 문서는 웹을 하나의 선택지로 되돌리고, 실험으로 필요성을 판정한다.

판정 대상은 "사용자가 더 보고 싶어 하는가"가 **아니다**. 사람은 뭐든 더 보고 싶어 하므로 그 기준은 항상 "웹 필요"로 귀결된다.
판정 대상은 **"사용자가 요구한 정보가 카카오 한도 안에 담기지 않는가"** 이다 (7절).

---

## 1. 설계를 강제하는 물리적 제약

카카오 스킬 응답 규격. 이 표가 3안의 형태를 결정했다.

| 타입 | 본문 한도 | 버튼 |
| --- | --- | --- |
| simpleText | 1,000자 (500자 초과 시 "더보기"로 접힘) | 불가 |
| textCard | 제목 50자 / 본문 **400자** | 가로 2개, 세로 3개 |
| basicCard | 제목 50자 / 본문 **230자** | 가로 2개, 세로 3개 |
| listCard | 항목 **5개**까지 (캐러셀 내 4개) | — |
| 캐러셀 | **10장** (listCard는 5장) | — |
| 버튼 라벨 | **14자** (가로 2개 배치 시 8자) | — |

파생 제약 두 가지:

1. 선행 문서가 정한 `결과 → 확인한 내용 → 확인하지 못한 내용 → 다음 행동` 4칸은 **basicCard 230자에 들어가지 않는다.** 결과는 textCard 400자를 쓴다.
2. **버튼을 누르면 새 스킬 호출이 발생한다.** 4초 예산이 새로 시작되고, 백엔드는 `job_id`로 직전 결과를 재조회해야 한다. 즉 A안과 B안 모두 "1차 응답 → 재조회"라는 **동일한 2단계 구조**를 갖는다. 두 안의 차이는 단계 수가 아니라 **2단계에 실을 수 있는 정보량**이다.

## 2. 3안 개요

| | A안 · 챗봇 완결 | B안 · 챗봇 + 상세 웹 | C안 · 행동 지시 |
| --- | --- | --- | --- |
| 2단계 매체 | 근거 캐러셀 (최대 5장) | 웹 상세 페이지 | 없음 |
| 상태 라벨 | 사용 (`위험 징후` 등) | 사용 | **사용하지 않음** |
| 근거 제공량 | 요약된 근거 4칸 | **관측 원자료 전량** (리다이렉트 홉, 관측 시각, 대조한 공식 도메인 목록) | 최소 |
| KISA 인계 | 위험 징후 시 | 위험 징후 시 | 위험 징후 시 |
| 핵심 가설 | 근거는 챗봇 안에 다 담긴다 | 챗봇에 못 담는 원자료가 이해에 필요하다 | **상태 라벨이 오독의 원인이다** |

세 안 모두 **KISA 인계는 위험 징후일 때만** 한다. 판단 보류까지 인계하면 KISA를 몰랐던 사용자까지 전부 밀어넣게 되고, 확인되지 않은 건으로 공식 창구를 과부하시킨다.

C안이 라벨을 버리는 이유: 오독의 1순위 후보가 `범위 내 이상 징후 미발견`이라는 **라벨 자체**다. 라벨 없는 안을 대조군으로 두어야 "라벨이 문제인가, 설명이 문제인가"를 실험으로 분리할 수 있다.

## 3. 화면 스케치

4개 화면만 만든다: ① 입력 안내 ② 위험 징후 ③ 범위 내 미발견 ④ 판단 보류.
②는 직관성이 높은 케이스, **③·④가 핵심인데 놓치기 쉬운 케이스**다. ②만 잘 되는 안은 의미가 없다.

기존 12개 상태 중 나머지(입력 부족, URL 여러 개, 분석 중, 처리 실패 등)는 3안이 서로 다르지 않으므로 비교에서 제외한다.

### 공통 규칙 (세 안 모두)

- 의심 URL은 링크·미리보기·이미지로 노출하지 않는다. 텍스트로만, 도메인 부분을 잘라 표기한다.
- **결과 카드에 한계 문장 1줄을 고정한다.** 대부분의 사용자는 2단계 버튼을 누르지 않는다. 한계를 버튼 뒤로 넘기면 버튼을 누르지 않은 사람에게는 사실상 안전 보증이 된다.
- 판정값에 `safe`는 없다.

### B안 · 챗봇 + 상세 웹

①~④의 **결과 카드 문구는 A안과 동일**하다. 다르게 만들면 문구 차이가 매체 차이를 오염시킨다.
차이는 오직 **2단계 버튼의 목적지**다.

## 4. 비교 루브릭

6축으로 평가한다. **①은 다른 축보다 무겁다.** 이 제품에서 틀리게 이해시키는 것은 잘못된 안전 보증을 준 것이므로, **①에서 진 안은 나머지를 다 이겨도 탈락**으로 다룬다.

| 축 | 정의 | 측정 |
| --- | --- | --- |
| ① **오독 위험** (최우선) | ③ 화면을 보고 "안전하다"로 이해하는가 | 실험 지표 ①, 첫 노출 안만 집계 |
| ② 도달 시간 | 결론까지 필요한 탭 수 | 설계상 확정 |
| ③ 이탈 지점 | 2단계 버튼을 실제로 누르는가 | 실험 지표 ② |
| ④ 근거 충실도 | 사용자가 요구한 정보를 담을 수 있는가 | 실험 지표 ②의 자유응답 |
| ⑤ 지연 예산 적합성 | `docs/latency-budget.md` 4초 안에 드는가 | 설계상 확정 |
| ⑥ 구현 비용 | 만들고 유지하는 비용 | 설계상 확정 |

### 설계상 확정되는 축 (실험 전에 채울 수 있음)

| | A안 | B안 | C안 |
| --- | --- | --- | --- |
| ② 도달 시간 (결론) | 1탭 | 1탭 | **1탭** |
| ② 도달 시간 (근거 전체) | 2탭 + 캐러셀 4회 스와이프 | 2탭 + 페이지 로드 | **불가** |
| ⑤ 지연 예산 | 1차 4초 / 2차 4초 (`job_id` 재조회, 캐시 적중) | 1차 4초 / 웹은 예산 밖 — **가장 여유** | 1차 4초만 |
| ⑥ 구현 비용 | `kakao-templates/` 캐러셀 추가 | **`frontend/` 전체 + 토큰 발급·만료 + 출력 가드** | 가장 낮음 |

### 장단점

**A안 · 챗봇 완결**

- 장점: 사용자가 카카오톡을 떠나지 않는다. 이탈 지점이 하나 적다. 웹 구현·배포·토큰 만료 처리가 전부 불필요해진다. `frontend/README.md`가 걱정한 "웹이 대상 페이지에 접근하는 사고" 경로 자체가 사라진다.
- 단점: 캐러셀 5장 × 230자가 상한이다. 리다이렉트 홉이 3개면 그것만으로 한 장을 다 쓴다. **가변 길이 목록을 담을 수 없다.**
- 놓치기 쉬운 위험: 캐러셀은 옆으로 넘겨야 보인다. **"확인하지 못한 것"이 3/4장에 있으면 대부분 안 본다.** 그래서 한계 1줄을 결과 카드에 고정했다(3절 공통 규칙). 이 고정이 없으면 A안은 성립하지 않는다.

**B안 · 챗봇 + 상세 웹**

- 장점: 정보량 제한이 없다. 관측 원자료를 그대로 보여줄 수 있어 "근거와 함께 알려준다"는 제품 정의에 가장 충실하다. 4초 예산 밖이라 시간 압박이 없다.
- 단점: 구현 비용이 압도적으로 크다. 토큰 발급·만료·무효 링크 화면까지 필요하다(선행 문서의 `상세 링크 무효` 상태).
- 놓치기 쉬운 위험: **스미싱을 의심 중인 사용자에게 링크를 누르라고 요구한다.** 우리가 가르치려는 행동("모르는 링크 누르지 마세요")과 정면으로 충돌한다. 경계심이 높은 사용자일수록 안 누른다 — 즉 **B안의 근거는 가장 조심스러운 사용자에게 가장 도달하지 않는다.** 이건 실험에서 반드시 관찰해야 한다.

**C안 · 행동 지시**

- 장점: 가장 짧고 가장 싸다. 상태 라벨이 없어 "미발견 = 안전" 오독 경로가 구조적으로 막힌다. 사용자가 실제로 원하는 것(안심하거나 신고·상담 받기)에 직접 답한다.
- 단점: 근거가 없다. 제품 정의("근거와 함께 알려준다")를 포기한다. 사용자가 왜 그런지 물으면 답할 경로가 없다.
- 놓치기 쉬운 위험: 근거가 없으면 **신뢰가 안 쌓인다.** 처음 한두 번은 따르지만, 챗봇이 왜 그렇게 말하는지 모르면 다음에 안 쓴다. 단발 이해도는 높고 재사용률은 낮을 가능성 — 1회성 실험으로는 잡히지 않는 위험이므로 결론에 명시한다.

## 5. 실험 설계

### 피험자

- 5~6명. 지인·가족 중심.
- **40대 이상 최소 2명 필수.** 동료 개발자만 쓰면 "이상 징후 미발견"을 정확히 해석해버려 ③·④의 오독 위험이 측정되지 않는다. 택배 스미싱의 실제 피해 분포를 반영해야 한다.
- 스미싱 문자를 실제로 받아본 적 있는 사람을 섞는다. 사전에 물어 기록한다.

### 자극물

`frontend/README.md`에 따라 **실제 스미싱 문자·URL은 쓰지 않는다.** 합성 문자 3종:

| | 내용 | 대응 화면 | 성격 |
| --- | --- | --- | --- |
| 문자1 | 가짜 도메인 (`nuri-post.example`) | ② 위험 징후 | 직관성 높은 케이스 |
| 문자2 | 공식 도메인이지만 확인 범위 제한 | ③ 범위 내 미발견 | **놓치기 쉬운 케이스** |
| 문자3 | URL 없이 전화번호만 | ④ 판단 보류 | **놓치기 쉬운 케이스** |

### 진행

- **within-subject** — 1명이 3안을 모두 본다. 순서는 라틴방격으로 돌린다(ABC / BCA / CAB).
- 3안 × 3문자 = 9회. 1인당 20분.
- 실제 폰에서 HTML 목업을 연다. 카카오톡은 **글자 수와 스크롤 길이가 곧 UX**라 종이·ASCII로는 "카드가 길어서 안 읽음" 같은 결정적 실패가 드러나지 않는다.
- 진행자는 화면을 설명하지 않는다. "직접 보고 판단해 주세요"만 말한다.

### 지표

**① 오독률** — 화면을 보여준 뒤 묻는다:

> *"이 문자, 친구한테 뭐라고 전달하시겠어요?"*

자유응답에 "안전하다 / 괜찮다 / 진짜다"가 나오면 오독 1건.
이해도를 직접 묻지 않고 재현시키는 질문이라 5명 규모에서 신뢰할 수 있다. 리커트 척도는 표본이 작아 무의미하고, 사람은 자기 이해도를 과대평가한다.

> **집계 규칙 — 이 실험의 유효성이 여기 달려 있다.**
> 오독률은 **각 피험자가 가장 먼저 본 안의 문자2 결과만** 집계한다.
> 한 번 "안전하다는 뜻이 아니다"를 이해하면 다음 안에서는 이미 아는 상태가 되어 측정이 무효가 된다.
> 2·3번째 안에서는 오독률을 세지 않고, 지표 ②·③만 기록한다.

**② 근거 요구** — 두 가지를 기록한다.

- 2단계 버튼(`자세히 보기` / `자세히 보기`)을 **진행자 유도 없이 스스로 눌렀는가** (Y/N)
- 눌렀든 안 눌렀든 묻는다: *"이 결과를 믿으려면 뭘 더 알아야 할 것 같으세요?"* — 자유응답 원문 그대로 기록

이 자유응답이 7절 판정의 원자료다.

**③ 선호 순위** — 9회를 마친 뒤 3안을 순위 매기고 이유를 묻는다. 참고용 보조 지표.

### 기록

`docs/experiments/` 에 `template.md` 형식으로 남긴다. 자유응답은 요약하지 않고 원문을 적는다.

## 6. 각 안이 이기는 조건 (실험 전 선언)

결과를 보고 해석을 맞추지 않기 위해, 먼저 적는다.

- **C안 승리**: 문자2에서 C안의 오독이 0이고 A·B안에서 오독이 발생하면 — 라벨이 범인이다. 세 안 모두에서 라벨을 버린다.
- **A안 승리**: 오독률이 세 안 비슷하고, 지표 ②의 자유응답이 전부 캐러셀 5장·230자에 담기는 수준이면 — 웹은 불필요하다.
- **B안 승리**: 7절 조건 충족.

## 7. 웹 필요성 판정 기준 (실험 전 고정)

> **B안(웹)은 다음을 모두 만족할 때에만 채택한다.**
>
> 1. 지표 ②의 자유응답에서, **과반(5명 중 3명 이상)** 이 결과를 믿기 위해 추가 정보를 요구했고,
> 2. 그 요구가 **캐러셀 5장 × 230자에 담기지 않는 종류**일 것 — 구체적으로 리다이렉트 홉 목록, 관측 시각·출처, 대조한 공식 도메인 목록처럼 **행 수가 가변인 목록**.

"더 보고 싶다"는 판정 대상이 아니다. **"무엇을"이 한도를 넘는지**가 판정 대상이다.

조건 2가 충족되지 않으면 — 즉 사람들이 원한 게 "왜 그렇게 판단했는지 한 줄 설명" 수준이면 — **`frontend/`의 웹은 근거 없는 구조이므로 축소하거나 폐기한다.** 그 경우 이 문서와 실험 기록이 폐기 근거가 된다.

B안이 채택되더라도 **4절에서 짚은 위험이 남는다**: 스미싱을 의심 중인 사용자에게 링크를 누르게 만드는 구조다. 실험에서 "안 눌렀다"가 많으면, 채택하더라도 진입 문구를 다시 설계해야 한다.
