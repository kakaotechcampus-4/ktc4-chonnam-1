# 카카오톡 채널에 챗봇 흐름 올리고 테스트하는 방법

- 작성일: 2026-09-18
- 상태: **R1~R3 네이티브 프로토타입 검증 완료, 사용자 테스트 미실행**
- 대상: 이미 만들어 둔 카카오톡 채널 `클릭 전 확인`
- 목적: 백엔드 판정 로직 없이, 관리자센터 화면만으로 UX 흐름을 올려 사용자 테스트를 한다.

흐름과 문구는 `docs/designs/chatbot-flow.md`, 결과 화면 3안은
`docs/designs/ux-options-3.md`, 실제 카드 검증 기록은
`docs/designs/kakao-result-card-prototype.md`를 따른다.

## 0. 먼저 알아야 할 것

### 이름이 바뀌었다

`카카오 i 오픈빌더` → **`챗봇 관리자센터`** (https://chatbot.kakao.com/).
옛 이름으로 검색하면 오래된 문서가 섞여 나온다.

### 사업자등록번호는 필요 없다

챗봇을 카카오톡 채널에 붙이는 데 비즈니스 채널 인증이나 사업자등록번호는 **필요 없다.**
실제로 현재 채널은 "비즈니스 정보 미인증" 상태인데도 챗봇이 붙어 스킬 응답까지 나온다.

혼동하기 쉬운 지점: **"비즈앱과 비즈니스 채널은 동일한 사업자 번호여야 한다"**는 조건은
카카오 디벨로퍼스 앱과 채널을 연결할 때(카카오싱크, 비즈플러그인) 이야기다.
챗봇 연결과는 별개다.

공식 연결 조건은 세 가지뿐이다.

| 조건 | 내용 |
| --- | --- |
| 권한 | 봇 마스터가 카카오톡 채널 **매니저 이상**, 디벨로퍼스 앱 **EDITOR 이상** |
| 중복 | 해당 채널에 다른 챗봇이 이미 연결돼 있으면 불가 |
| 기능 충돌 | **채팅방 리스트 메뉴, 자동응답 메시지 메뉴가 켜져 있으면 불가** |

출처: [채널과 챗봇은 어떻게 연결하나요](https://cs.kakao.com/helps_html/1073196934?locale=ko)

### 비즈플러그인은 쓰지 않는다

`인증 블록`, 개인정보 수집 동의 플러그인 같은 **비즈플러그인**을 쓰면 그때는 비즈니스 채널이
필요하다. 약관 동의는 일반 버튼과 텍스트로 처리해 이 경로를 피한다.
서류 없이 갈 수 있고 일정도 흔들리지 않는다.

### 요금

챗봇 관리자센터와 챗봇 채팅 서비스는 **무료**다. Event API 메시지만 건당 15원(VAT 별도).

출처: [챗봇은 무료인가요](https://cs.kakao.com/helps_html/1073202191?locale=ko) ·
[챗봇 관리자센터 개요](https://kakaobusiness.gitbook.io/main/tool/chatbot/start/overview)

## 1. 개발 채널로 연결한다

테스트 전에 이것부터 한다.

| 채널 구분 | 반영 시점 |
| --- | --- |
| 운영 채널 | **배포해야** 반영. 배포는 시작하면 중지할 수 없고 **최대 30분** 소요 |
| 개발 채널 | **저장하면 즉시** 반영 |

문구를 고쳐가며 테스트하려면 개발 채널이어야 한다. 30분짜리 배포를 기다릴 수 없다.

- 위치: 챗봇 관리자센터 → 설정 → 카카오톡 채널 연결
- **데모 당일에 배포하지 않는다.** 하루 전에 끝낸다.

출처: [봇 설정](https://kakaobusiness.gitbook.io/main/tool/chatbot/main_notions/bot_setting)

## 2. 블록으로 화면을 만든다

블록 하나가 화면 한 장이다. 버튼에 "이 블록으로 가기"를 걸면 화면이 넘어간다.
종이 프로토타입을 카카오톡 안에서 만드는 셈이다. **백엔드가 없어도 된다.**

### 만드는 자리

블록 상세화면 아래 **봇 응답 형식 설정** → `+` → 타입 선택

| 타입 | 용도 |
| --- | --- |
| 텍스트형 | 버튼 없는 짧은 안내 (약관, 복사 방법) |
| 카드형 | 이미지 + 제목 + 본문 + 버튼 (결과 카드, 웰컴) |
| 이미지형 / 커머스형 / 리스트형 | 이번 설계에서 안 씀 |
| 스킬 | 백엔드 응답을 그대로 말풍선으로 (5절) |

**카드형에서 카드를 여러 장 추가하면 캐러셀이 된다.** 근거 화면 3장이 여기 해당한다.

버튼: `버튼 추가` → 버튼 이름 + **연결할 블록** 선택.
말풍선 아래 `바로연결`(Quick Reply)도 블록 호출이 된다.

출처: [봇 응답 꾸미기](https://i.kakao.com/docs/tutorial-chatbot-response) ·
[튜토리얼 2단계](https://kakaobusiness.gitbook.io/main/tool/chatbot/tutorial/make_chatbot/tutorial_2)

### 기본 제공 블록

봇을 만들면 자동으로 생기고 **삭제할 수 없다.** 수정은 된다.

| 블록 | 언제 뜨나 |
| --- | --- |
| 웰컴 블록 | 채널 연결 후 대화방에 처음 들어올 때 1회 |
| 폴백 블록 | 사용자 발화가 **어떤 블록과도 맞지 않을 때** |
| 탈출 블록 | 되묻기 중에 대화를 초기화하고 싶을 때 |

**폴백 블록이 우리 핵심 경로다.** 사용자가 붙여넣는 스미싱 문자는 어떤 발화 패턴에도
맞지 않으니 폴백으로 간다. 현재 채널에서 `약관~`이라고 입력했을 때 스킬 응답이 돌아온 것으로
보아 폴백에서 스킬 서버까지 도달하는 것이 확인됐다.

주의: 공식 문서는 폴백 블록에 대해 **"'텍스트형' 말풍선 형태로 작성할 수 있습니다"**라고만
적고 있다. 폴백에서 카드형을 직접 쓸 수 있는지는 **확인 못 함.** 스킬 응답으로 카드를
내보내는 경로는 실제로 동작하므로, 카드가 필요하면 스킬을 쓴다.

출처: [블록](https://kakaobusiness.gitbook.io/main/tool/chatbot/main_notions/block)

## 3. 만들 블록 목록

| 블록 | 응답 타입 | 버튼 → 연결 블록 |
| --- | --- | --- |
| 웰컴 블록 | 카드형 | `동의하고 시작` → 문자 확인하기 / `내 문자는 어떻게 쓰이나요` → 약관 |
| 약관 | 텍스트형 | `동의하고 시작` → 문자 확인하기 / `다음에 할게요` → 웰컴 |
| 문자 확인하기 | 카드형 | `문자 복사하는 법` → 복사 안내 |
| 복사 안내 | 텍스트형 | `돌아가기` → 문자 확인하기 |
| 신고·상담 받기 | 카드형 | KISA 연결 |
| 결과 R1~R6 | 카드형 | 상태별 행동 버튼 + `자세히 보기` → 근거 R1~R6 |
| 근거 R1~R6 | 카드형 **3장(캐러셀)** | 3장 모두에 같은 행동 버튼 |

결과 블록 6개는 **문구를 하드코딩한다.** 판정 로직은 이 테스트에 필요 없다.
검증하려는 것은 "이 화면을 본 사람이 링크를 누르지 않는가"이지 판정의 정확도가 아니다.

## 4. 봇 리스트 메뉴 (상시 노출 메뉴)

공식 명칭은 **봇 리스트 메뉴**다. 대화방 하단에서 쓸어 올려 여는 슬라이드 메뉴다.

- 위치: 챗봇 관리자센터 → 시나리오 설정 → `봇 리스트 메뉴 설정` 켜기. 모든 시나리오 공통
- 버튼이 할 수 있는 일: **블록 연결 / 메시지 전송** 두 가지뿐
- 넣을 것 3개: `문자 확인하기`, `신고·상담 받기`, `내 문자는 어떻게 쓰이나요`

### 확인 못 한 것

| 항목 | 상태 |
| --- | --- |
| 최대 개수 | **확인 못 함** — 직접 켜서 확인 |
| 1단/2단 계층 | **확인 못 함** — 공식 문서에 하위 메뉴 언급 없음 |
| 버튼명 글자수 | 문서 간 불일치: 시나리오 문서 14자 / 튜토리얼 20자 |

**혼동 주의:** 검색에 자주 나오는 "최대 20개 저장, 10개 노출"은 봇 리스트 메뉴가 아니라
카카오톡 채널의 별개 기능인 **채팅방 메뉴** 수치다. 그리고 채팅방 메뉴를 켜면
챗봇 연결 자체가 불가능하다(0절 기능 충돌). 둘은 같이 못 쓴다.

## 5. 결과 화면을 테스트에서 띄우는 방법

사용자가 합성 문자를 붙여넣으면 챗봇은 그게 M1인지 M3인지 모른다. 두 가지 길이 있다.

| 방법 | 어떻게 | 평가 |
| --- | --- | --- |
| A. 진행자가 조작 | `문자 확인하기` 블록에 임시 버튼 6개(R1~R6)를 두고 진행자가 눌러줌 | 오늘 바로 됨. 사용자가 버튼을 보므로 어색함 |
| B. 스킬에 고정 응답 | 스킬 서버가 문자 속 도메인만 보고 R1~R6 중 하나를 고정 반환 | 진짜처럼 보임. 반나절 작업 |

**B를 권한다.** 스킬 서버는 이미 붙어 있고, 합성 문자 6통의 도메인이 전부 다르다.

| 도메인 | 반환 |
| --- | --- |
| `nuri-post.example` | R1 위험 징후 |
| `nuri-delivery.example` | R2 이상 징후 미발견 |
| `short.example` | R3 판단 보류 |
| `nuri-parcel.example` | R4 처리 실패 |
| `track-nuri.example` | R5 분석 중 |
| URL 없음 | R6 주소 없음 |

`if` 6줄이면 끝난다. **판정 로직이 아니라 테스트용 고정 응답**이라는 사실을 코드 주석과
파일 이름에 남긴다. 이 코드가 `CLAUDE.md` 절대 원칙 1의 "결정적 판정 로직"으로
오해되면 안 된다.

B로 가면 결과 카드는 블록이 아니라 스킬 응답 JSON이 된다. `자세히 보기` 버튼은
`block` action으로 근거 캐러셀 블록에 연결한다. 캐러셀은 관리자센터에서 만들어 둔다.

## 6. 스킬 연동 제약

| 항목 | 내용 |
| --- | --- |
| 방식 | **POST**, 요청·응답 모두 JSON body |
| 주소 | **공인 IP 또는 공중망 도메인만 가능.** 로컬 환경은 동작하지 않음 |
| HTTPS 필수 여부 | **확인 못 함** — 1차 출처에서 못박는 문장을 찾지 못함 |
| 타임아웃 | **5초. 봇 작업자가 조정 불가** |
| 초과 시 | 스킬 서버 연결 오류로 분류되고 말풍선이 발송되지 않을 수 있음 |
| 인증 | 스킬 등록 시 `헤더값` 필드에 인증 키 지정 가능. 테스트용 `테스트 헤더값` 별도 |
| 콜백 | `{"version":"2.0","useCallback":true}` 반환 후 `callbackUrl`로 POST. **1회 한정.** 유효시간이 문서마다 1분/5분으로 엇갈림 |

`CLAUDE.md`의 "콜백은 제한된 임시 기능이라 의존하지 않는다"는 판단은 유지한다.
유효시간 수치조차 공식 문서가 엇갈린다.

로컬 개발: 카카오가 안내하는 공식 방법은 관리자센터의 **Test URL + 스킬 테스트** 기능이다.
ngrok은 "공인 도메인이 필요하다"는 제약을 푸는 수단이지 카카오가 안내한 방법은 아니다.

### 등록 방법

챗봇 관리자센터 → 스킬 → 생성 → 스킬명 + URL(필수), Test URL / 헤더값(선택).
수정 시 `새 버전으로 저장`으로 버전 관리.
블록 연결: 블록의 **파라미터 설정** 영역 → 스킬 선택.

출처: [스킬 만들기](https://kakaobusiness.gitbook.io/main/tool/chatbot/skill_guide/make_skill)

## 7. 문구 한도 (설계에 직접 걸리는 숫자)

출처: [응답 타입별 JSON 포맷](https://kakaobusiness.gitbook.io/main/tool/chatbot/skill_guide/answer_json_format)

| 항목 | 한도 |
| --- | --- |
| 한 응답의 말풍선 | **최대 3개** |
| 버튼 이름 | **14자. 가로로 2개 놓으면 8자** |
| 버튼 배치 | 가로 최대 2개 / 세로 최대 3개 |
| 버튼 action | `webLink` `message` `phone` `block` `share` `operator` |
| simpleText | 1,000자. 단 **500자 넘으면 "전체 보기"로 접힘** |
| basicCard | 제목 50자 / 본문 **230자** |
| textCard | 제목 50자 / 본문 단일 400자, 캐러셀 128자 |
| listCard | 항목 최대 5개, 캐러셀 안에서는 4개 |
| 캐러셀 | **최대 10장.** listCard 캐러셀은 5장 |
| 캐러셀 이미지 | **전부 1:1 또는 전부 2:1로 통일해야 함** |
| 관리자센터 이미지 업로드 | 프로토타입에서 **최대 500KB**, 와이드형 800×400 권장 확인 |
| 바로연결(Quick Reply) | 최대 10개 |

확인 못 함: listCard 항목 글자수, 바로연결 버튼 글자수, 이미지 용량·포맷.

## 8. 실제 개발 채널 확인 결과

개발 채널 `클릭 전 확인`의 `시나리오 02`에 `PROTOTYPE_` 접두사로 실험 블록을 분리했다.
R1~R3 결과 카드와 `자세히 보기` 캐러셀을 스마트폰 카카오톡에서 확인했다.

| 입력 | 표시 결과 |
| --- | --- |
| `카드 테스트` | 프로토타입 진입 카드 |
| `결과1 테스트` | 공식 주소와 다름 |
| `결과2 테스트` | 다른 점을 못 찾음 |
| `결과3 테스트` | 확인할 정보가 부족함 |

`자세히 보기`만 공통 캐러셀과 연결했다. 신고·상담, 공식 경로, 다시 보내기는 아직
실제 기능과 연결하지 않았다. R4~R6 네이티브 카드와 사용자 테스트도 후속 범위다.

## 9. 진행 순서

1. 개발 채널로 연결 바꾸기 → 저장이 즉시 반영되는지 확인
2. 웰컴 + 약관 + 문자 확인하기 3개만 만들고 폰에서 눌러보기
3. 봇 리스트 메뉴 3개 켜서 최대 개수·계층 제약 확인 (4절 미확인 항목)
4. 근거 캐러셀 3장 만들어 230자 안에 들어가는지 확인
5. 스킬에 R1~R6 고정 응답 넣기
6. 팀원 대상 리허설 → 캠퍼스 동기 → 팀 밖 5명

## 10. 사후 제재 (참고)

사전 심사는 없지만 사후 제재가 있다.

| 제재 | 내용 |
| --- | --- |
| BLOCK-Bot | 봇 차단. 누적되면 영구 제한 가능 |
| BLOCK-Message | 일정 기간 메시지 발송 불가 |
| BLOCK-Block | 특정 블록 차단, 해당 응답 제거 |

우리 제품은 스미싱을 다루므로 **실제 스미싱 문자와 실제 택배사 이름을 쓰지 않는다.**
합성 문자와 가상 브랜드 `누리택배`, 예약 도메인 `.example`을 쓰는 이유가 여기에도 있다.

## 11. 조사 한계

- `i.kakao.com/docs`와 `chatbot.kakao.com/docs`는 이번 조사에서 접근에 실패했다(타임아웃 10회 이상).
  본문 인용은 카카오가 운영하는 `kakaobusiness.gitbook.io/main/tool/chatbot`과
  카카오 고객센터에서 확보했다.
- `i.kakao.com/docs/skill-dev-guide`에 스킬 요청 payload 전체 필드표, HTTPS 필수 여부,
  포트 제한이 있을 가능성이 높다. 구현 전에 브라우저로 직접 열어 확인한다.
- 위 표에서 **확인 못 함**으로 표시한 항목은 추측하지 않았다.
