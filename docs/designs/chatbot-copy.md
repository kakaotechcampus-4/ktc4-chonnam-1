흐름을 바꾸는 결정은 이 문서가 아니라 `chatbot-flow.md`에서 한다.

## 2. 구체화한 흐름

```
[웰컴 블록 W1]  ← 채널 최초 1회만
  [문자 확인하기]              → B1
  [내 문자는 어떻게 쓰이나요]     → W2

[개인정보 안내 W2]  ← 정보 보기 전용. 동의 버튼 없음
  [문자 확인하기]              → B1

[봇 리스트 메뉴]  ← 상시
  [문자 확인하기] → B1   [신고·상담 받기] → B3   [내 문자는 어떻게 쓰이나요] → W2

[문자 확인하기 B1]
  [문자 복사하는 법]           → B2
[복사 안내 B2]
  [돌아가기]                  → B1

[신고·상담 받기 B3]  ← 상황부터 고른다
  [문자만 받았어요] → B3a      [링크를 눌렀어요] → B3b
[문자만 받음 B3a]
  [118 전화하기] [문자 확인하기]
[링크를 누름 B3b]

                    │

                    │
        ┌───────────┴───────────┐
       아니오                    예
        │                        │
       E1                  URL 개수 확인
                                 │
              ┌──────────┬───────┴───────┐
            0개        2개 이상         1개
              │          │              │
             R6         R7              │
                                         │
                     BE: 전송 동의 기록이 있는가?  ← BE 미구현
                                         │
                                ┌────────┴────────┐
                               없음               있음
                                │                  │

                  [동의하고 확인하기] ─────────────┤
                                                   │

R1 [신고·상담 받기] [자세히 보기]      R2 [공식 앱 열기] [자세히 보기]

  C1 확인한 것 → C2 확인 못 한 것 → C3 지금 할 일
```

**링크만 온 경우(엣지 4)는 별도 분기가 아니다.** URL 1개 경로를 그대로 타고 R1~R4로 간다(D6).
결과 카드 아래에 `문자 본문도 보내기`를 선택 버튼으로 둘 수 있으나 필수가 아니다.

**폴백 블록의 스킬 응답으로 카드가 표시된 프로토타입은 확인했다.**
`kakao-chatbot-build-guide.md` 2절의 미확인 항목은 이 검증 기록과 구분해 갱신한다.
현재 폴백은 `render` 스킬 응답을 사용하지만, E1·R1~R7의 BE 분기·카드 반환과
콜백 완료 말풍선은 아직 검증되지 않았다.

## 3. 화면별 문구

글자수는 스크립트로 셌다. 한도는 `kakao-chatbot-build-guide.md` 7절
(제목 50자 / basicCard 본문 230자 / 버튼 14자·가로 2개면 8자).
**이모지는 카드 제목과 본문에만 쓰고 버튼에는 쓰지 않는다.** R1은 `⚠️` 하나만 쓴다.

### W1 웰컴

| | |
| --- | --- |
| 제목 | `📩 클릭 전에 먼저 확인하세요` (16자) |
| 본문 | `택배 문자 속 주소가 공식 주소와 같은지 확인해 드려요.`<br>`주소가 공식 주소와 다른지까지만 확인해요. 안전하다고 보장해 드리는 건 아니에요.` (78자) |
| 버튼 | `문자 확인하기`(7) → B1 / `내 문자는 어떻게 쓰이나요`(14) → W2 — **세로 배치** |

이전 초안의 `동의하고 시작`은 화면만 넘기고 동의를 받지 않았다. 버튼 이름과 실제
동작을 맞추려고 `문자 확인하기`로 바꿨다(`chatbot-flow.md` 9절 (1)).
이미지는 넣지 않는다. 웰컴 이미지 자산이 오면 본문 위 공백이 생기지 않는지
실기기에서 확인한 뒤 넣는다(9절 (3)).

### W2 개인정보 안내

| | |
| --- | --- |
| 제목 | `🔒 내 문자는 어떻게 쓰이나요` (16자) |
| 본문 | **문구 보류** — 문자 원문 로깅, 외부 URL 전송, 결과 저장·삭제 정책 확인 후 작성 |
| 버튼 | `문자 확인하기`(7) → B1 |

정보를 보는 화면이다. 동의는 W3에서만 받는다.

현재 BE 코드는 원문 발화를 로그에 출력하고 URL을 외부 urlscan에
`visibility=public`으로 전송한다. 이는 `docs/PRD.md`의 비공개 분석 전제와도
다르므로 BE·PM 확인이 필요하다.
그래서 “확인이 끝나면 바로 지운다”, “따로 보관하지 않는다”는 문장을 아직
사용자에게 약속할 수 없다. 이 절의 문구는 정책·구현 확인 전까지 배포 대상이 아니다.

### W3 전송 동의 (신규)

동의 기록이 없는 사용자가 확인할 문자를 보냈을 때 스킬 응답으로 보낸다.
관리자센터 블록이 아니다.

| | |
| --- | --- |
| 제목 | `🔒 확인하려면 동의가 필요해요` (16자) |
| 본문 | `문자를 확인하려면 문자 내용과 주소를 외부 분석 서비스로 보내야 해요.`<br>`동의하시면 방금 보낸 문자를 바로 확인할게요.` (65자) |
| 버튼 | `동의하고 확인하기`(9) → 보류한 문자로 분석 시작 / `내 문자는 어떻게 쓰이나요`(14) → W2 — **세로 배치** |

- `다음에 할게요` 버튼은 두지 않는다. 누르지 않으면 아무 일도 일어나지 않는다.
- 본문은 **초안**이다. 어떤 서비스로 무엇을 보내는지는 W2 정책 확인 후 고친다.
- BE가 동의를 기록하고 전송 조건에 연결하기 전에는 배포하지 않는다.
- BE가 문자를 보류할 수 없으면 두 번째 줄을 `동의하신 뒤 문자를 한 번 더 보내주세요.`로 바꾼다.

### B1 문자 확인하기 (붙여넣기 안내)

| | |
| --- | --- |
| 제목 | `📋 문자를 그대로 붙여넣어 주세요` (18자) |
| 본문 | `의심되는 문자를 복사해서 아래 입력창에 붙여넣고 보내주세요.`<br>`자르지 말고 문자 전체를 그대로 보내주시면 더 정확해요. 결과는 최대 1분쯤 걸릴 수 있어요. ⏱` |
| 버튼 | `문자 복사하는 법`(9) → B2 — **세로 전용** |

`최대 1분쯤`은 `latency-budget.md`의 상한 60초를 사용자 말로 옮긴 것이다(D1).
문자 삭제·보관에 관한 안내는 W2의 정책·구현 확인 전까지 넣지 않는다.
동의 문구와 `동의하고 시작` 버튼은 넣지 않는다. 관리자센터의 현재 B1 카드에 있다면 뺀다.

### B2 복사 안내

| | |
| --- | --- |
| 제목 | `📱 문자 복사하는 법` (11자) |
| 본문 | `1. 문자 앱에서 확인할 문자를 열어요`<br>`2. 문자 내용을 손가락으로 꾹 눌러요`<br>`3. 뜨는 메뉴에서 '복사'를 눌러요`<br>`4. 여기로 돌아와 입력창을 꾹 누르고 '붙여넣기'를 눌러요` (98자) |
| 버튼 | `돌아가기`(4) → B1 |

### B3 신고·상담 받기

| | |
| --- | --- |
| 제목 | `☎️ 지금 어떤 상황인가요?` (15자) |
| 본문 | `상황에 맞는 방법을 바로 알려드릴게요.` (21자) |
| 버튼 | `문자만 받았어요`(8) → B3a / `링크를 눌렀어요`(8) → B3b — 세로 |

이전 초안은 긴 설명 뒤에 상담 버튼 3개를 두었다. 급한 사용자가 설명을 읽고 채널까지
골라야 했다. 이제 상황부터 고르게 한다(`chatbot-flow.md` 9절 (2)).
`링크를 눌렀어요`에는 정보를 입력했거나 앱을 설치한 경우도 포함한다(B3b 본문에서 밝힌다).

### B3a 문자만 받음 (신규)

| | |
| --- | --- |
| 제목 | `📵 링크는 누르지 마세요` (13자) |
| 본문 | `링크를 누르지 않았다면 문자를 지우고 보낸 번호를 차단하세요.`<br>`신고하고 싶다면 118에 전화하세요. 24시간 무료예요.` (66자) |
| 버튼 | `118 전화하기`(8) — `phone` 액션 / `문자 확인하기`(7) → B1 — 세로 |

"피해가 없어요" 같은 안심 문장은 쓰지 않는다. 할 일만 말한다.

### B3b 링크를 누름 (신규)

| | |
| --- | --- |
| 제목 | `🚨 지금 바로 상담받으세요` (14자) |
| 본문 | `링크를 눌렀거나, 정보를 입력했거나, 앱을 설치했다면 바로 상담받으세요.`<br>`전화 118은 24시간 무료예요. 챗봇·채팅 상담 시간: [확인 필요]` (80자, 시간 확정 전) |
| 버튼 | `전화 상담 118`(9) — `phone` 액션 / `챗봇 상담`(5) / `채팅 상담`(5) — 세로 3개 |

시간 정보는 버튼 바로 위 마지막 줄에만 둔다. 챗봇·채팅 상담의 운영 시간은
관리자센터 현재 카드와 KISA 공식 안내로 확인한 뒤 채운다(7절).

### R1 공식 주소와 다름

| | |
| --- | --- |
| 제목 | `⚠️ 공식 주소와 달라요` (13자) |

### R4 확인을 못 마침

| | |

| 본문 | `확인을 끝내지 못했어요. 위험한지 아닌지 아직 알 수 없어요.`<br>`잠시 뒤에 문자를 그대로 다시 보내주세요.` (59자) |

⚠️ **관리자센터 원본의 `보내주신 문자에는 문제가 없어요`를 쓰지 않는다.**
`kakao-fe-be-integration.md` 3절이 지적한 대로, 분석 실패 상황에서 **안전 보증처럼 읽힌다.**
위 문구는 "확인을 못 했다"와 "그래서 아직 모른다"를 함께 말해 그 오독을 막는다.
관리자센터 원본과 BE 전달본을 이 문구로 통일해야 한다.
관리자센터 R4의 현재 버튼은 `다시 해보기` 한 개다. `처음으로` 추가는 이 문서의
후속 제안이며 아직 화면에 반영되지 않았다.

R3과 R4를 나누는 이유는 **사용자가 할 일이 다르기 때문**이다.
R3은 "보낸 것에 확인할 게 없다"(사용자 조치 필요), R4는 "우리 쪽이 못 했다"(그대로 재시도).
문구에서 내부 상태 이름(`판단 보류` `처리 실패`)은 쓰지 않고 원인만 다르게 쓴다.

### R5 분석 중 (첫 응답)

**카드가 아니라 글자만 보낸다.** 콜백 대기 응답은 `useCallback: true`와 `data.text`만
담고 `template`을 넣지 않는다([카카오 AI 챗봇 콜백 개발 가이드](https://kakaobusiness.gitbook.io/main/tool/chatbot/skill_guide/ai_chatbot_callback_guide)).
바로연결(`quickReplies`)도 `template` 안에 있으므로 제목·버튼·바로연결을 쓸 수 없다.

| | |
| --- | --- |
| `data.text` | `⏳ 문자 속 주소를 확인하고 있어요. 1분쯤 걸릴 수 있어요.`<br>`그동안 문자 속 링크는 누르지 마세요.`<br>`1분이 지나도 결과가 안 오면 '결과 확인'이라고 보내주세요.` (91자) |

공식 도메인이 일치하면 이 화면을 거치지 않고 바로 R2로 간다(D2).
`그동안 문자 속 링크는 누르지 마세요`가 이 화면의 핵심이다 — 대기 시간이 최대 1분이라,
기다리는 동안 사용자가 링크를 눌러버리는 것이 가장 큰 위험이다.

버튼을 달 수 없으므로 결과 확인 방법은 문장으로 알린다. 콜백이 실패했을 때 사용자가
결과를 다시 보는 경로는 K 결과 확인이다. `data.text`의 글자수 한도는 문서에 없다.
실기기에서 줄바꿈과 잘림을 확인한다.

### K 결과 확인 (신규)

사용자가 `결과 확인`이라고 보내거나 바로연결 `결과 확인`을 누르면 스킬이 답한다.
관리자센터에 `결과 확인` 블록을 만들고 스킬을 연결한다. 블록 발화 예시는
`결과 확인` `결과` `결과 알려줘` `결과 어떻게 됐어`다.
BE는 카카오 사용자 ID로 **그 사용자의 가장 최근 작업**을 찾는다. 사용자가 작업 번호를
입력하지 않는다. 작업 상태는 BE PR #25의 `running` `completed` `timeout` `failed`를 따른다.

**K1 아직 확인 중** (`running`)

| | |
| --- | --- |
| 제목 | `⏳ 아직 확인하고 있어요` (13자) |
| 본문 | `조금만 기다렸다가 다시 '결과 확인'을 눌러 주세요.`<br>`그동안 문자 속 링크는 누르지 마세요.` (51자) |
| 바로연결 | `결과 확인`(5) |

"결과가 나오면 바로 알려드릴게요"는 쓰지 않는다. 콜백 주소가 만료됐으면 결과가 알아서
오지 않는다.

**K2 결과 다시 보기** (`completed`)

- 첫 말풍선(`simpleText`): `{HH:MM}에 확인한 결과예요.` — 한국 시간
- 이어서 저장한 결과 카드(R1~R3)를 그대로 보낸다. R2·R3는 말풍선이 2개라 합쳐 3개다(한도 3개).
- 다시 분석하지 않는다. 확인 시각을 붙이는 이유는 이 결과가 **그 시각의 페이지 상태**라서다.

**K3 확인 실패** (`timeout` `failed`)

- R4 카드를 그대로 보낸다. 실패를 위험 근거처럼 말하지 않는다(`result-meaning-cases.md` 4절 사례 5).

**K4 결과 없음** (작업을 찾지 못함)

| | |
| --- | --- |
| 제목 | `📭 최근 확인한 결과가 없어요` (16자) |

| 버튼 | `문자 확인하기`(7) → B1 |

"보낸 문자가 없어요"라고 쓰지 않는다. 지금 BE 작업 저장소는 메모리에만 있어서 서버가
재시작하면 보낸 문자의 결과도 사라진다. 사용자를 탓하는 문장이 되면 안 된다.

새로 보낸 문자는 분석하지 않고 보관하지도 않는다. 지금 BE는 같은 상황에
`simpleText`("이전 요청을 아직 확인하고 있어요…")로 답한다. 이 카드로 바꾼다.

## 4. 자세히 보기 캐러셀 3장

순서는 `확인한 것 → 확인 못 한 것 → 지금 할 일`이다.

현재 관리자센터의 공통 캐러셀 3장에는 이 행동 버튼이 아직 없으므로 구현 후

## 5. 이미지 현황과 후속 검토

`kakao-fe-be-integration.md` 2절 기준으로 R1~R4·R6·R7 카드는 이미 관리자센터에 있다.
카드가 있다는 사실과 이미지 파일이 있다는 사실은 다르다. 대기 안내 R5는 콜백 대기
응답이라 글자만 보낼 수 있다(3절 R5). 관리자센터 카드와 이미지가 필요 없다.

| 화면 | 현재 확인한 이미지 자산 | 나타낼 상태 |
| --- | --- | --- |
| R1 | 저장소 프로토타입 이미지 있음 | 주소가 공식과 다름 |
| R2 | 저장소 프로토타입 이미지 있음 | 비교했으나 차이 없음 — **안전 표시로 읽히면 안 됨** |
| R3 | 저장소 프로토타입 이미지 있음 | 확인할 정보 부족 |
| R4 | 현재 관리자센터 카드에 이미지 없음 | 확인을 마치지 못함 |
| R6 | 현재 관리자센터 카드에 이미지 없음 | 확인할 주소 없음 |
| R7 | 저장소 자산 없음. 관리자센터 이미지 여부 확인 필요 (BE 전달 범위 밖) | 주소가 여러 개 |
| R5 | 이미지 불가 — 콜백 대기 응답은 글자만 보낸다 | 분석 중 — 결과가 아님이 드러나야 함 |

- 규격: 800×400 (2:1), 500KB 이하. 기존 프로토타입과 동일.
- 원본 위치: `kakao-templates/assets/prototype/`
- 브랜드·URL·동적 문구는 이미지에 넣지 않는다. 상태만 나타낸다.
- 캐러셀 이미지는 **전부 1:1 또는 전부 2:1로 통일**해야 한다(build-guide 7절).
- **이미지 주소가 없으면 썸네일을 넣지 않고 텍스트 카드로 보낸다**(`chatbot-flow.md` 9절 (3)).
  빈 썸네일은 카드 상단에 큰 흰 공백을 만든다. BE 템플릿(`r1`~`r3`)의
  `{{ image_url }}`는 지금 렌더러가 채우지 않는다. BE에 전달할 사항이다.

### 실기기 확인 항목

카드 길이와 핵심 버튼 위치는 FE가 조정할 수 있다. 카카오의 하단 메뉴와 입력창 위치는
바꿀 수 없다. 아래는 안드로이드 카카오톡에서 화면마다 확인한다. 기기·OS·카카오톡 버전과
캡처를 함께 기록한다.

| 확인할 것 | 통과 기준 |
| --- | --- |
| 첫 화면에서 핵심 버튼이 보이는가 | 카드가 도착한 직후 스크롤 없이 제목과 첫 버튼이 보인다 |
| 카드 상단 공백 | 썸네일이 없거나, 있으면 이미지가 실제로 표시된다 |
| 회색 본문 가독성 | 핵심 행동이 본문이 아니라 **제목**이나 버튼에 있다. 본문 색은 관리자센터에서 바꿀 설정을 찾지 못했다 (확인 필요) |
| 큰 글씨 설정 | 기기 글꼴과 카카오톡 글자 크기를 가장 크게 했을 때 제목·버튼 글자가 잘리지 않는다 |
| 가로 버튼 2개 | 8자 버튼이 한 줄에 들어가고 잘리지 않는다 |
| 다크 모드 | 이미지 배경이 어두운 화면에서 튀지 않는다 |

## 6. 이모지 정책

| 규칙 | 이유 |
| --- | --- |
| 카드 제목에 1개, 본문에 최대 1개 | 더 넣으면 안내문이 장식으로 읽힌다 |
| **버튼에는 쓰지 않는다** | 버튼 8자(가로 2개) 한도를 이모지가 잡아먹어 가로 배치가 깨진다 |
| **R1은 `⚠️` 하나만** | 위험 결과에 다른 이모지가 붙으면 심각도가 희석된다 |
| 실패·거절 화면(R3·R4·R6·R7·E1)은 사용자를 탓하지 않는 이모지 | `❌` `🚫`는 사용자 잘못으로 읽힌다 |

글자수는 파이썬 `len()` 기준으로 셌다. 카카오가 이모지를 2자로 세는지는 확인하지 못했다.
가장 긴 제목이 18자(B1)라 50자 한도에는 여유가 충분하다.
