# 카카오 결과 카드–BE 연동 명세

- 작성일: 2026-09-22 · 갱신: 2026-10-02 (BE PR #40 연결 반영)
- 상태: BE가 FE 카드로 응답하고, 개발 채널에서 콜백·결과 확인까지 동작을 확인함. 결과 카드 고르는 규칙 수정은 남음(2절)
- 범위: 카카오 개발 봇의 카드 응답. 상세 웹은 [ADR 0005](../adr/0005-no-detail-web.md)에 따라 이번 범위에서 제외

## 1. FE·BE 소유 경계

```text
사용자 입력 → 카카오 챗봇 → BE 스킬 서버 → 카카오 응답 JSON → 카드
```

- **FE**: 카드 문구·버튼·흐름. 카드 JSON 원본은 `frontend/kakao-templates/cards/`, 빈칸 목록과
  블록 ID는 같은 폴더 `README.md`, 문구 근거는 [`chatbot-copy.md`](./chatbot-copy.md).
- **BE**: 입력 처리, 분석 결과에 맞는 카드 고르기, 빈칸 채우기, 스킬 응답과 콜백.
- BE는 FE 폴더의 카드 JSON을 **직접 읽는다**(`services/kakao_card_renderer.py`). 사본을 따로 두지 않는다.
  `backend/src/server/templates/kakao_templates/`는 옛 사본이다.
- 카드 문구를 바꾸려면 FE 폴더의 JSON만 고치면 된다. BE는 FE 브랜치를 합치면 반영된다.
- 실제 서버는 루트 `main.py`의 `/kakao/skill` 하나다. 문자 확인(폴백)과 결과 확인 블록이 같은 스킬을 쓴다.

## 2. 상황별 카드

| 상황 | 카드 | 비고 |
| --- | --- | --- |
| 링크 없는 문자 | R6 `r6-input-required` | 콜백 없이 첫 응답에서 끝남 |
| 같은 사용자가 분석 중에 또 보냄 | K5 `k5-duplicate` | 새 문자는 분석하지 않음 |
| 첫 응답 (분석 시작) | R5 `r5-analyzing` | 콜백 대기 응답. 6절 |
| 분석 실패, 45초 초과 | R4 `r4-unavailable` | 2026-10-02 PR #40은 콜백으로 보내는 45초 초과·오류가 아직 텍스트(`main.py` `run_analysis_and_callback`). 결과 확인으로 다시 볼 때는 R4 |
| 분석 완료 | 아래 "결과 카드 고르기" | 콜백으로 보냄 |

**결과 카드 고르기** (임시 규칙, 위에서부터 차례로)

| # | 조건 | 카드 |
| --- | --- | --- |
| 1 | 문자·페이지 `signals`가 1개 이상 | R1 `r1-lookalike` |
| 2 | `url.official == "official"` + 문자·페이지 모두 `no_risk_found` | R2 `r2-official` |
| 3 | `url.official == "brand_mismatch"` | R8 `r8-not-official` |
| 4 | 나머지 (`official`인데 2번이 아님, `not_registered`, `unresolved`) | R9 `r9-uncertain` |

- `result`는 지금 항상 `false`라서 카드 고를 때 쓰지 않는다.
- 페이지 수집기(격리 환경)가 없어 페이지 분석은 늘 `not_run`이다. 그래서 2번은 지금 나오지 않는다.
  격리 환경 전까지 공식 주소도 R9로 두기로 했다(2026-10-02, [`result-meaning-cases.md`](./result-meaning-cases.md) 6절 9).
- 목록에 없다는 이유만으로 위험 카드를 보내지 않는다(PR #39 멘토 리뷰). `brand_mismatch`는 R1이 아니라 R8이다.
- **2026-10-02 기준 BE PR #40은 이 표와 다르다.** `brand_mismatch` → R1, `not_registered` → R8로 한 칸씩
  밀려 있고, `message.brand`가 `"unknown"`이어도 R8을 보내 "택배사(unknown)"가 표시됐다. PR #40 코멘트로 수정 요청함.
- 스캐너 점수(`url.scan.score`)는 판정에 쓰지 않는다. 위험 쪽으로만 반영할지(멘토 B안)는 AI·BE 미결정 안건이다.

## 3. 빈칸과 버튼

- 빈칸은 `{{ 이름 }}` 형태다. 목록과 채우는 규칙은 `frontend/kakao-templates/README.md`와
  [`chatbot-copy.md`](./chatbot-copy.md) 4절 "빈칸 채우는 규칙"을 따른다.
- `org_name`은 `message.brand`다. `unknown`이면 넣지 않는다(R8 대신 R9).
- 버튼 `blockId`는 관리자센터 블록 ID로 채워 두었다(2026-10-01). 블록을 다시 만들면 ID가 바뀌므로 README 표와 카드를 같이 고친다.
- 결과 카드의 `자세히 보기` 버튼에는 BE가 `extra.job_id`를 넣는다. 버튼을 누르면 `action.clientExtra.job_id`로 온다.
  **이 요청을 받아 `c-detail-carousel`을 보내는 경로는 아직 없다.**
- 입력된 의심 URL을 버튼 링크·미리보기로 만들지 않는다.
- 공식 도메인 즉답은 지금 없다. 모든 링크가 urlscan을 거친다.

## 6. 결과 확인 연동 규칙 (2026-09-26 작성, 2026-10-02 BE PR #40 기준 갱신)

화면 문구는 [`chatbot-copy.md`](./chatbot-copy.md) 3절 R5·K1~K5, 흐름 결정은
[`chatbot-flow.md`](./chatbot-flow.md) 9절 (4)에 있다. 이 절은 BE가 지킬 연결 규칙이다.

### 대기 응답 (R5)

- `{"version": "2.0", "useCallback": true, "data": {"text": "…"}}` 형식으로 보낸다.
  `template`은 넣지 않는다. 카드·버튼·바로연결을 쓸 수 없다.
- `data.text`는 FE 문구(`r5-analyzing.json`)를 그대로 쓴다. 버튼이 없으므로 마지막 줄은
  "「결과 확인」이라고 보내 주세요"다.
- **실제 화면에는 관리자센터 폴백 블록의 `Callback 설정` 대기 메시지가 나온다**(2026-10-06 개발 채널 확인).
  이 칸이 비어 있으면 `data.text`를 보내도 대기 문구가 보이지 않는다. 문구를 바꿀 때는 관리자센터를 고친다.

### 결과 확인 블록 (K)

| 작업 상태 | 응답 |
| --- | --- |
| `running` | K1 카드 + 바로연결 `결과 확인` |
| `completed` | `simpleText` `{HH:MM}에 확인한 결과예요.` + 저장해 둔 결과 카드 |
| `timeout` `failed` | R4 카드 |
| 작업 없음 | K4 카드 |
| `running` 중 새 문자 | K5 카드 + 바로연결 `결과 확인`. 새 문자는 분석·보관하지 않는다 |

- **결과 확인 요청은 `intent.name == "결과 확인"`으로 알아본다.** 발화 글자(`utterance`)로 비교하면
  관리자센터에 등록한 다른 발화(`결과 알려줘` 등)가 문자 분석으로 빠진다.
- **조회 키는 카카오 사용자 ID다.** 스킬 요청의 사용자 ID로 그 사용자의 가장 최근
  작업을 찾는다. 작업 번호를 사용자에게 보이거나 입력받지 않는다. 다른 사용자의
  결과가 나가면 안 된다.
- **K2는 다시 분석하지 않는다.** 콜백으로 보낸(또는 보내려던) 응답 JSON과 확인 시각을
  작업에 함께 저장해 두고 그대로 보낸다. 확인 시각은 작업의 `completed_at`(UTC 저장)을 한국 시간으로 바꾼 값이다.
- 말풍선은 최대 3개다. K2는 시각 말풍선 1개 + 결과 카드 1개다.
- 작업은 서버 메모리에만 있다. Render 재시작·재배포 뒤에는 K4가 나간다.
- `GET /api/analyses/{job_id}`는 카카오가 부르는 경로가 아니다. 결과에 문자 분석
  내용이 들어가므로 외부에 공개할지 BE가 확인한다.
