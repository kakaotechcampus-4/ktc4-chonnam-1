# 카카오 결과 카드–BE 연동 명세

- 작성일: 2026-09-22
- 상태: FE→BE 전달 내용과 검증 항목 정리. 실제 스킬 응답 연결은 아직 검증 전
- 범위: 카카오 개발 봇의 결과 카드. 상세 웹은 [ADR 0005](../adr/0005-no-detail-web.md)에 따라 이번 범위에서 제외

## 1. FE·BE 소유 경계

```text
사용자 입력 → 카카오 챗봇 → BE 스킬 서버 → 카카오 응답 JSON → 결과 카드
```

FE는 관리자센터의 카드 문구·이미지·버튼·흐름을 만들고 화면을 검증한다.
BE는 입력 처리와 판정 결과에 맞는 카카오 응답 JSON 조립, 스킬 응답 및 콜백을
담당한다. 관리자센터의 정적 카드가 BE의 응답에 자동으로 적용되지는 않는다.

FE·BE는 카드 전달 형식을 **JSON**으로 합의했다. FE는 현재 카드의 JSON 사본을
브랜치 생성 전에 BE 담당자에게 **파일로 직접 전달**했다. BE는 그 사본을
`backend/`의 템플릿 구현에 사용해 시험한다. 이 브랜치에는 JSON 사본을 중복
보관하지 않는다. 이 문서는 두 파트의 연결 규칙과 남은 검증을 기록한다.
후속 화면 문구 초안은 [`chatbot-copy.md`](./chatbot-copy.md)에 따로 기록한다.
그 초안은 아직 관리자센터 카드나 BE 전달 JSON에 반영된 결과가 아니다.

## 2. 현재 카드와 상태의 관계

| 카드 | 관리자센터 상태 | BE 측 입력·판정과 연결할 때 확인할 점 |
| --- | --- | --- |
| R1 `공식 주소와 다름` | 이전 작업에서 제작 | `smishing_suspected` 중 `reason_code=lookalike` 문구에만 맞음 |
| R2 `다른 점 못 찾음` | 이전 작업에서 제작, 카드 응답 2개 | 공식 도메인 대조 결과와 실제 미확인 항목을 함께 표시. 안전 보증 금지 |
| R3 `정보 부족` | 이전 작업에서 제작, 카드 응답 2개 | 현재 본문은 주소를 찾지 못한 경우를 설명함. 모든 `inconclusive` 사유에 그대로 적용하지 않음 |
| R4 `확인 실패` | 이번 작업에서 제작 | `not_analyzable` 등 확인을 마치지 못한 경우. 안전 보증으로 읽히는 문구 수정 필요 |
| R6 `문자 속 URL이 없을 때` | 이번 작업에서 제작 | URL이 없는 새 요청에 사용. 스캔을 시작하지 않음 |
| R7 `주소가 여러 개` | 이번 작업에서 제작 | URL 여러 개의 입력 처리용. 이번 JSON 전달 범위에는 포함하지 않음 |

관리자센터에서 R5 카드와 `[결과 확인]` 버튼은 확인되지 않았다. BE에 전달한
JSON은 R1·R2·R3·R4·R6의 **다섯 파일**이다. `FinalState` 값과 카드 번호는
서로 다른 개념이다. 특히 R1·R3은 사유를 무시하고 상태값 하나만으로 문구를
고르면 사실과 다른 안내가 될 수 있다.

## 3. 출력 규칙

- 카드 제목·본문·응답 순서·버튼 기능은 FE가 전달한 JSON을 기준으로 한다.
  R2와 R3은 각각 말풍선 두 개가 이어진다.
- 이미지가 있는 카드의 `thumbnail.imageUrl`에는 카카오가 접근할 수 있는
  **공개 HTTPS 주소**를 넣는다. 저장소의 로컬 이미지 경로는 그대로 보낼 수 없다.
- 관리자센터의 블록 연결 버튼을 스킬 JSON으로 옮길 때는 현재 봇의 `blockId`를
  사용하고, 실제 카카오톡에서 이동 동작을 확인한다. 입력된 의심 URL을 버튼
  링크·미리보기로 만들지 않는다.
- 확인하지 않은 항목을 확인 완료로 표현하지 않는다. 공식 도메인 일치 즉답은
  페이지 스캔을 기다리지 않으므로, 페이지 내용을 확인하지 않았음을 표시한다.
- R4 관리자센터 원본의 “보내주신 문자에는 문제가 없어요”는 분석 실패 상황에서
  안전 보증처럼 읽힐 수 있다. BE 전달본과 관리자센터 원본의 문구를 대조하고,
  실제 사용자 응답 전에 사실에 맞게 통일해야 한다.

## 4. 이번 연결 시험과 후속 범위

BE가 상태별 합성 입력으로 JSON 응답을 재현하면 FE는 카카오 개발 채널에서
카드 제목·본문·이미지·버튼·말풍선 순서를 확인한다. URL이 없는 R6은 외부
스캔 없이 먼저 확인할 수 있다. 실제 스미싱 URL 대신 합성 입력과 팀 소유
모형 주소를 사용한다.

현재 `develop`의 `backend/src/server/main.py`는 URL 없는 입력에 `simpleText`를
반환하고, URL 검사 결과에도 카드 렌더러를 사용하지 않는다. 따라서 FE가
JSON을 전달했다는 사실과 **카카오 채널 연결 완료**는 구분해 기록한다.

`[결과 확인]` 버튼, 분석 결과 저장·재조회는 이번 카드 연결 시험에 포함하지
않고 후속 작업으로 둔다. [ADR 0003](../adr/0003-kakao-callback.md)의 콜백 실패
시 조회 폴백 결정은 유지된다. 구현 전에는 콜백 실패 후 사용자가 결과를 다시
조회할 경로가 없다. 연동 규칙은 6절에 정리했다(2026-09-26).

## 5. 공동 검증 항목

- BE가 반환한 R1·R2·R3·R4·R6 카드가 개발 채널에서 의도한 화면으로 표시되는가
- R2·R3의 두 말풍선 순서가 유지되는가
- 버튼이 의도한 블록으로 이동하고 의심 URL을 열지 않는가
- R1·R3·R4의 문구가 실제 판정 사유와 확인 범위를 넘어서 단정하지 않는가
- 지연 요청의 첫 응답과 최종 콜백을 각각 확인했는가

검증 시 합성 입력, BE 응답 JSON, 카카오 화면 캡처, 통과 여부를 함께 기록한다.

## 6. 결과 확인 연동 규칙 (2026-09-26, BE PR #25 기준)

화면 문구는 [`chatbot-copy.md`](./chatbot-copy.md) 3절 R5·K1~K5, 흐름 결정은
[`chatbot-flow.md`](./chatbot-flow.md) 9절 (4)에 있다. 이 절은 BE가 지킬 연결 규칙이다.

### 대기 응답 (R5)

- `{"version": "2.0", "useCallback": true, "data": {"text": "…"}}` 형식으로 보낸다.
  `template`은 넣지 않는다. 카드·버튼·바로연결을 쓸 수 없다.
- `data.text`는 FE 문구를 그대로 쓴다. 지금 코드의 "링크를 확인하고 있어요…"를 바꾼다.

### 결과 확인 블록 (K)

| 작업 상태 | 응답 |
| --- | --- |
| `running` | K1 카드 + 바로연결 `결과 확인` |
| `completed` | `simpleText` `{HH:MM}에 확인한 결과예요.` + 저장해 둔 결과 카드 |
| `timeout` `failed` | R4 카드 |
| 작업 없음 | K4 카드 |
| `running` 중 새 문자 | K5 카드 + 바로연결 `결과 확인`. 새 문자는 분석·보관하지 않는다 |

- **조회 키는 카카오 사용자 ID다.** 스킬 요청의 사용자 ID로 그 사용자의 가장 최근
  작업을 찾는다. 작업 번호를 사용자에게 보이거나 입력받지 않는다. 다른 사용자의
  결과가 나가면 안 된다.
- **K2는 다시 분석하지 않는다.** 콜백으로 보낸(또는 보내려던) 응답 JSON과 확인 시각을
  작업에 함께 저장해 두고 그대로 보낸다. 확인 시각은 한국 시간이다.
- 말풍선은 최대 3개다. K2의 시각 말풍선 1개와 R2·R3 결과 카드 2개를 합치면 3개로 한도에 맞는다.
- `GET /api/analyses/{job_id}`는 카카오가 부르는 경로가 아니다. 결과에 문자 분석
  내용이 들어가므로 외부에 공개할지 BE가 확인한다.

### 공동 검증 항목

| 시나리오 | 기대 화면 |
| --- | --- |
| 콜백 성공 후 `결과 확인` | K2 (콜백 결과와 같은 카드) |
| 콜백 전송 실패 후 `결과 확인` | K2 |
| 분석 중 `결과 확인` | K1 |
| 분석 중 새 문자 | K5 |
| 서버 재시작 후 `결과 확인` | K4 |
| 확인 시간 초과 후 `결과 확인` | R4 |
