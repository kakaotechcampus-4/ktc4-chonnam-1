# 업무별 공식 안내(norm_rules) 운영 연결 설계

- 작성: 2026-10-11
- 상태: 승인 (사용자, 2026-10-11)
- 범위: RAG 멘토 피드백 로드맵 3단계(업무별 규범 자료)의 운영 연결
- 관련: PR #39 멘토 리뷰, `ai/src/ai/kb/norm_rules/`, `docs/designs/chatbot-copy.md` 4절(자세히 보기), #68

## 1. 목적

멘토 피드백: "사용자에게는 문자에서 확인한 사실, 검사하지 못한 부분, 문자에 적힌 링크나 연락처를 쓰지
않고 해당 업무를 확인할 방법을 알려주면 됩니다."

`norm_rules/` 의 공식 자료 중 **확인 경로**와 **공식 절차**를 출처·시점과 함께 사용자에게 보여 준다.

성공 기준: 택배 문자(그리고 금융 + 전화 응대 문자)를 넣으면 "자세히 보기"에 "이 업무는 이렇게 직접
확인하세요"가 **검토를 마친 자료의 문장으로만** 나온다. 업무를 알 수 없으면 아무것도 붙이지 않는다.

## 2. 지키는 원칙

- **판정에 쓰지 않는다** (CLAUDE.md 원칙 1·2). 결과(`result`), `answer`, 카드 선택에 영향을 주지 않는다.
- **LLM 을 쓰지 않는다.** 고르는 것은 정해진 값만 보는 결정적 규칙이다. 문자 원문·`IsolatedPage.info`
  같은 자유 텍스트는 보지 않는다. 공격자가 만든 페이지 문장에 휘둘리지 않기 위해서다.
- **스키마를 바꾸지 않는다.** `AnalysisResponse`(`docs/scheme.md`)는 그대로다. AI 는 함수를 제공하고
  BE 가 부른다. 의존 방향은 BE → AI 그대로다 (원칙 4).
- **정식(`curated`) 자료만 쓴다.** `draft` 는 어디에도 나가지 않는다.
- **단정하지 않는다.** 공식 절차는 "OO는 ~라고 안내했어요(연도)"로 보여 줄 수 있게 출처·시점을 함께
  넘긴다. "그래서 이 문자는 가짜"라는 결론을 붙이지 않는다.

## 3. 함수

`ai/src/ai/kb/guidance.py` (새 파일)

```python
@dataclass(frozen=True)
class Guidance:
    kind: str           # "verification" | "procedure"
    text: str           # 자료의 statement 그대로
    source: str         # 첫 번째 출처의 name
    published_at: str   # 첫 번째 출처의 게시일 (YYYY-MM-DD)
    rule_id: str        # NR-XXXX

def find_guidance(result: AnalysisResponse | Mapping) -> list[Guidance]: ...
```

- 입력은 **최종 결과 전체**(`url`·`message`·`env`). BE 가 카드에 쓰는 `final_payload` dict 도 받는다.
  "자세히 보기"는 최종 결과가 나온 뒤 누르는 화면이라 시점이 맞다.
- `env` 가 `not_run` 이어도 `message`·`url` 값으로 동작한다. 격리 환경이 붙으면 `env` 값이 함께 쓰인다.
- **예외를 던지지 않는다.** 입력이 이상하거나 맞는 자료가 없으면 `[]`.
- 자료는 처음 부를 때 읽어 캐시한다(`search.py` 의 KB 로드와 같은 방식). 네트워크 없음.
- 사칭 수법(`impersonation`) 자료는 돌려주지 않는다. 사용자 안내가 아니라 수법 설명이다.
- 순서는 확인 경로 → 공식 절차, 같은 종류 안에서는 `rule_id` 순. **최대 3개.**
  "자세히 보기" 캐러셀 카드 1장이 128자(textCard 캐러셀)라 많이 넘겨도 다 보여 줄 수 없다.

## 4. 고르는 규칙 — 자료 파일의 `match`

규칙은 코드가 아니라 각 자료 앞부분의 `match` 에 적는다. 검토자가 자료와 적용 조건을 한 번에 본다.

```yaml
match:
  - {category: 택배}                          # 목록의 항목 중 하나라도 맞으면 적용
  - {category: 금융, doubts: 전화 응대}        # 한 항목 안의 조건은 모두 맞아야 함
```

- 쓸 수 있는 키: `category`(Topic 값), `brand`(Brand 값), `doubts`(MessageDoubt 값), `official`(DomainMatch 값).
- `category`·`brand` 는 `message` 와 `env` 중 어느 쪽이 맞아도 된다. `doubts` 는 `message.details.doubts` 의 값.
- `match` 가 없는 자료는 적용하지 않는다.
- 값은 enum 에 있는 값만 쓴다. 데이터 테스트가 검사한다.

이번에 붙이는 규칙:

| 자료 | 종류 | match |
|---|---|---|
| NR-0015 택배 고객센터 직접 확인 | verification | `category: 택배` |
| NR-0011 우체국 | procedure | `brand: 우체국택배` |
| NR-0012 한진택배 | procedure | `brand: 한진택배` |
| NR-0013 롯데택배 | procedure | `brand: 롯데택배` |
| NR-0014 로젠택배 | procedure | `brand: 로젠택배` |
| NR-0019 카드사 고객센터 직접 확인 | verification | `category: 금융, doubts: 전화 응대` |

연결하지 않는 것: 과태료(NR-0002~0009, 지역별 자료인데 정해진 값에 지역·기관이 없음),
신한카드·한국소비자원 절차(NR-0017·0018, 기관을 알아볼 정해진 값이 없음), 사칭 수법(NR-0010·0016).

## 5. 알려진 한계와 결정 보류

정해진 값으로는 해외결제·과태료를 정확히 알아볼 수 없다. 주제(`Topic`)가 "금융"·"공공기관"까지만
나뉘어, 은행 대출 문자나 검찰·정부지원금 문자와 구분되지 않는다.

결정(사용자, 2026-10-11): 지금 값으로 먼저 만들고, 로드맵 평가 단계(4단계 평가셋 확장)에서 해외결제·과태료
문자를 놓치는 비율을 잰 뒤 주제에 "결제·승인"·"과태료"를 더할지 정한다.

검토 중 측정(2026-10-11, 고정 규칙만, AI 추출 요구 행동 제외):

- 해외결제·카드 사칭 문자(평가 스미싱 12건 + NR-0016 연결 KB 사례 13건)의 주제는 `금융` 0건, 모름 17,
  쇼핑 6, 택배 2(`해외배송` 단어 때문). 요구 행동 `전화 응대` 도 0건. 그래서 NR-0019 의 `금융 + 전화 응대`
  조건은 사실상 붙지 않는다. NR-0019 는 draft 로 두고 평가 단계에서 조건을 다시 정한다.
- 택배 주제 스미싱 11건 중 8건은 택배사를 알 수 없다. NR-0015 를 `category: 택배` 전체에 거는 근거다.
- `[우체국]` 처럼 "우체국"만 쓴 문자는 `brand` 가 unknown 이다(`우체국택배` 만 인식). 그래서 NR-0011 은 이런 문자에
  붙지 않는다. 택배사 인식 규칙 보완을 평가 단계에서 함께 본다.

## 6. 검토 기준 (draft → curated)

검토자: 사용자(강성윤). Claude 가 아래 항목별 확인 결과를 보여 주고, 사용자가 승인하면 Claude 가
`status: curated`, `reviewer: 강성윤`, `reviewed_at: <승인일>` 을 채운다.

1. 발췌문(`quote`)이 출처 원문에 그대로 있는가 — 원문을 내려받아 기계로 대조한 결과를 첨부한다.
2. `statement` 가 발췌문이 직접 말하는 범위를 넘지 않는가.
3. 적용 범위(`applies_to`: 기관·지역·시점)와 `exceptions` 가 출처와 맞는가.
4. 출처가 아직 열리는가, 더 최신 공지가 있는가.
5. 전화번호가 지금도 맞는가.
6. `match` 가 자료의 적용 범위보다 넓지 않은가.

이 기준은 `ai/src/ai/kb/README.md` 와 `norm_rules/template.md` 에 옮겨 적는다.

## 7. 테스트

- 규칙별로 맞는 자료가 나온다 (택배 → NR-0015, 우체국택배 → NR-0015 + NR-0011, 금융 + 전화 응대 → NR-0019).
- `draft` 자료는 나오지 않는다 (테스트용 임시 자료 폴더로 확인).
- 업무를 모르면 `[]`. `env` 가 `not_run` 이어도 동작한다.
- 이상한 입력(빈 dict, 키 누락, 모르는 값)에도 예외 없이 `[]`.
- 최대 3개, 확인 경로가 먼저.
- 데이터 검사: `match` 키·값이 허용 목록과 enum 에 있는지.
