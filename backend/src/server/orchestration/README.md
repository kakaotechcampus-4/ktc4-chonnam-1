# backend/src/server/orchestration

BE의 핵심 로직. ①~⑥ 파이프라인 흐름 전체를 조율하고, 조회 한도·이중 검증 같은 가드레일을 강제합니다.

## 파이프라인 단계와 이 폴더의 역할

| 단계 | 이 폴더가 하는 일 | AI에게 위임하는 일 |
| --- | --- | --- |
| ① 해석·분류 | `clients/`로 요청 전달, `links.length ≠ 1` 결정론적 분기 (B03) | 실제 해석·분류 (AI-01, AI-02) |
| ② (삭제됨) | 아무것도 하지 않음 — ①에서 바로 ③으로 | — |
| ③ 관측 | `tools/`를 통해 외부 격리 분석 API 큐잉, 결과 저장 (B05, B07) | "다음에 어떤 도구를 쓸지" 판단만 (AI-11) |
| ④ 대조 | `clients/`로 요청, 응답의 `cited_rule_ids ⊆ matched_rules` 검증 (B12) | 실제 대조·해석 (AI-07) |
| ⑤ 보강 판단 | 조회 횟수 원자적 카운트, 한도 도달 시 AI 재호출 없이 종료 (B09, B10) | "더 조사할지/보류할지" 판단 (AI-11) |
| ⑥ 응답 조립 | 근거 카드 4칸 조립, 세션 상태 갱신, 웹 진입 토큰 발급 (B11, B20) | 없음 |

## 핵심 불변식 (반드시 테스트로 고정)

1. 관측 필드가 비어 있으면 ④ 호출 자체를 시작하지 않고 즉시 판단 보류를 반환한다.
2. 조회 횟수 카운트와 한도 체크는 원자적 트랜잭션으로 처리한다 (동시 요청 레이스 컨디션 방지).
3. AI가 인용한 규범 ID가 실제 검색 결과 집합의 부분집합이 아니면, `interpretation`을 null로 덮어쓰고 `mismatch_found=false` 처리한다.
4. 세션이 `analyzing` 상태인 동안 들어오는 새 요청은 새 작업을 만들지 않는다.
