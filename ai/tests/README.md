# 코드 검증

아래는 구현 시 갖춰야 할 검증 기준이며 테스트 구현 완료를 뜻하지 않는다.

- 브랜드·주장 목적·요구 행동을 원문 근거와 함께 추출하고 누락·모호한 항목은 미확인으로 남긴다.
- 텍스트만·링크만·둘 다 있음·여러 링크·빈 입력 분기를 AI 설계와 맞춘다.
- RAG는 링크를 제외한 마스킹 본문을 사용하며 검색 실패를 유사도 0으로 바꾸지 않는다.
- 관측이 고정된 상태에서 RAG 유사도·스캐너 점수·brands만 바꿔도 최종 판정은 유지한다.
- 발견·검사 후 미발견·미확인과 관측·모델 해석·사례를 구별한다.
- 모델·검색 실패 시 확인된 근거를 보존하고 설명 실패 시 템플릿을 사용한다.
- 미검토 KB와 근거 없는 인용·설명을 제외한다.
- 자체 sandbox와 자율 보강 도구 호출이 프로토타입 흐름에 없는지 확인한다.
- 세부 규칙이 확정되면 네 가지 최종 상태, 일부 관측 실패와 근거 충돌을 검증한다.

고정 fixture와 가짜 모델·스캐너 응답을 사용한다. 상세 계약 테스트는 스키마 확정 후 추가한다. 장시간 작업 저장·조회는 BE 통합 검증과 연결하되 이 문서가 구현 계약을 새로 정하지 않는다. 검증된 실행 명령은 구현 후 추가하고 품질 평가는 eval에 둔다.
