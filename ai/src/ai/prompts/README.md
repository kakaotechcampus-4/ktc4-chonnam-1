# 프롬프트 관리

프로토타입 설계의 역할별 지침은 다음과 같다. 문서 존재가 실행 코드 연결이나 스키마 구현 완료를 뜻하지 않는다.

| 파일 | 용도 |
|---|---|
| v1/parse_classify.md | 브랜드·주장 목적·요구 행동 추출. `categories` 는 주제 분류이지 위험 신호가 아니다 |
| v1/signals.md | 관측과 본문에서 위험 신호를 **근거와 함께 제안**. 최종 판정 권한 없음 |
| v1/compare.md | 확정된 판정과 관측을 사람이 읽을 문장으로 설명. 판정을 바꾸지 않음 |

문자·관측·검색 자료는 지시와 분리한다. 추출에는 링크를 제외하고 개인정보를 마스킹한 본문을 사용한다. 검색 사례를 실제 관측으로 바꾸지 않는다.

출력 의미는 AI 설계 문서를 따른다. 구체적인 JSON·필드·함수 계약은 후속 확정하며 기존 프롬프트의 필드명을 확정 계약으로 취급하지 않는다.

변경 전후 동일 평가셋으로 회귀를 확인하고 버전·해시와 변경 이유를 기록한다. 미구현 기능의 평가는 미실행으로 남긴다.
