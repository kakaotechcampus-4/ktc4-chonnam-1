# 파이프라인

기준은 [AI 설계](../../../../docs/ai/smishing-message-intake-ai.md)의 분석 흐름이다.

1. 백엔드가 텍스트와 링크를 분리한다.
2. 텍스트가 있으면 브랜드·주장 목적·요구 행동을 추출한다. URL을 제외하고 개인정보를 마스킹한 본문으로 피해 사례를 검색한다.
3. 링크 하나에 대한 백엔드의 공식 도메인 정보와 공통 관측 결과를 받는다.
4. 결정적 코드가 도메인과 관측 사실로 최종 상태를 결정한다. 코드 배치와 세부 규칙은 별도 확정한다.
5. 메시지 추출 결과·관측·설명·미확인 사항과 판정에 영향을 주지 않는 RAG 참고 정보를 조립한다.

| 입력 | 처리 |
|---|---|
| 텍스트와 링크 1개 | 메시지 추출·RAG 및 링크 분석 |
| 링크만 1개 | 추출·RAG 생략, 링크 분석만 사용 |
| 텍스트만 | 추출·RAG 참고 정보와 링크 입력 요청. 최종 판정 없음 |
| 링크 여러 개 | 하나를 선택하도록 요청 |
| 둘 다 없음 | 문자 입력 요청 |

관측 미확인과 검사 후 미발견을 구분한다. 관측 없는 사이트 설명은 생성하지 않는다. 모델·검색 실패가 확인된 근거를 지우지 않으며 설명 실패는 템플릿으로 폴백한다.

프로토타입은 자체 격리 분석을 호출하지 않는다. 근거 부족은 판단 보류, 필요한 분석 수행 실패는 분석 불가로 구별한다. 일부 단계 실패가 전체 분석 불가를 자동으로 뜻하지는 않는다.

장시간 작업은 백엔드가 계속 처리·저장하고 사용자 결과 확인 요청에 응답한다. AI는 카카오 콜백에 의존하지 않는다. 진행 상태와 최종 판정은 구분하며 시간 한도는 공통 지연 예산 및 후속 합의에 따른다.
