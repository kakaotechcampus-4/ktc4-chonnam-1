## 이전 기록과 비교

이전 기록 [2026-10-03-rag-tfidf-split](2026-10-03-rag-tfidf-split.md) 은 출처 원문(`text`)으로 검색했다.
그 리포트는 그대로 보존한다. 이번에는 같은 KB·같은 TF-IDF 설정에서 질의만 `message` 로 바꿨고,
기준값은 dev 에서 다시 골랐다.

| 항목 | 이전 (`text`) | 이번 (`message`) |
|---|---|---|
| 기준값 (dev 에서 고름) | 0.2102 | 0.2345 |
| dev hard negative 부착률 | 4.6% | 4.6% |
| dev 스미싱 hit@3 | 45.2% (14/31) | 41.9% (13/31) |
| test 스미싱 hit@3 | 25.8% (8/31, 13.7%~43.2%) | 29.0% (9/31, 16.1%~46.6%) |
| test 정상 부착률 | 6.7% (163행) | 3.1% (160행) |
| test hard negative 부착률 | 12.0% (150행) | 8.1% (148행) |

- test hit@3 차이는 1건이고 95% 구간이 거의 겹친다. 검색 성능이 나아졌다는 근거가 아니다.
  운영과 같은 조건으로 다시 잰 **기준선**이며, 이후 개선은 이 수치와 비교한다.
- 운영 기준값 `ai/src/ai/kb/search.py` 의 `DEFAULT_MIN_SIMILARITY` 를 0.2345 로 맞췄다.

### 평가에서 뺀 행

`SSG.COM`(4행)·`APPLE.COM`(1행)이 든 test 정상·hard negative 5행에 `exclude` 를 붙여 뺐다.
실제 도메인이면서 문장 안에서는 발신자·가맹점 이름으로 쓰여, BE 가 주소로 지울지 정해지지 않았다.
주소 규칙으로 고른 행이고 점수를 보고 고르지 않았다. 다만 그중 `H-address_correction-08` 은
사례가 잘못 붙던 행이라(top-1 0.2436), 빼기 전 test hard negative 부착률은 8.7%(13/150)였다.
dev 행은 없어 기준값은 바뀌지 않는다.
